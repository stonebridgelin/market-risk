# 旧补充历史的标签影响量化（2026-10-01）

这是冻结路径上的局部纠错核算，不是重新选参；不修改任何已入库的历史输出。只使用 2009-09-30 以前的 SPX、QQQ 收盘价，以及两套标签。

## 背景

此前 v1.3、v1.4 补充历史（窗口末日 2009-09-30）的损失计算使用了开发期标签（截止 2016-12-30）。开发期标签里有一个 SPX 事件（高点 2009-09-22，T0 与低点 2009-10-02）跨过窗口末日，它的危险区间把窗口末端的 SPX 区间标为危险。按 2009-09-30 截止生成的标签里，截止日时两个资产都还在寻峰，这些区间属于“尾段（寻峰）未定”。

## 核算了什么

| 版本 | 对象 |
| --- | --- |
| v1.3 补充历史（P0 稳健性） | P0 九组（K ∈ {3, 5, 10} × θ_P ∈ {1.5%, 2.0%, 2.5%}）与四条参照行（始终绿、黄、红，200 日均线） |
| v1.4 补充历史（纯价格版） | 纯价格版九组与四条参照行 |

两个版本的窗口相同：j₀′ = 1999-09-07 至 2009-09-30，2532 个区间。

做法：信号、执行暴露、日期轴与损失函数都不变，同一条计算路径分别用开发期标签与截止日标签各算一次。在整个窗口内逐日比对两套标签对每个资产区间的归类（危险、非危险、未定），凡归类不同的都纳入核算。按登记规则，未定区间的三项价格损失记零，日期保留在平均暴露的分母中。

## 结果

**归类不同的资产区间：两个版本都是 12 个**，起点日为 2009-09-22、23、24、25、28、29：

- SPX 6 个：危险 → 尾段（寻峰）未定。
- QQQ 6 个：非危险 → 尾段（寻峰）未定。

除这 12 个之外，整个窗口内两套标签的归类逐日相同。

**各对象的变化**（截止日标签 − 开发期标签）：

| 对象 | 主损失 L 的变化 | 其中 SPX 部分 | 其中 QQQ 部分 | T 的变化 |
| --- | --- | --- | --- | --- |
| 始终绿 | −0.031932 | −0.031351 | −0.000581 | 0 |
| 始终红 | +0.004711 | 0 | +0.004711 | 0 |
| 200 日均线 | −0.031932 | −0.031351 | −0.000581 | −0.016788 |
| v1.3 P0 九组 | −0.032425 至 −0.028204 | −0.028568 | −0.003857 至 +0.000364 | −0.025776 至 −0.015527 |
| v1.4 纯价格版九组 | −0.033914 至 −0.029694 | −0.030235 | −0.003679 至 +0.000542 | −0.026889 至 −0.018601 |

主损失的量级在 12 至 24 之间，T 在 −0.13 至 −3.47 之间；变化都在小数点后第二位。切换项、漏报罚项、区间数与平均暴露都不变。两份旧报告都没有 T价格，所以不报。逐对象、逐分项的原值、截止日标签下的值与差值见报告与 `objects.csv`。

**是否改变排序或结论：**

- 九组设定之间按主损失、按 T 的排序：两个版本都**没有改变**。
- 与参照行的比较方向（九组设定 × 四条参照行 × 主损失与 T）：两个版本都**没有改变**（0 项）。
- 原报告中的文字结论：两份报告的正文是表格与口径说明，没有比较优劣的文字结论。与标签有关的三句话在截止日标签下不再成立——“危险标签取自完整标签文件”、“跨窗口末端，不纳入”一节列出的 SPX 事件（截止日标签下它不是事件）、“被排除的资产区间：无”（截止日标签下每组设定有 12 个资产区间因尾段未定而不计价格损失）。

**其余用到这批标签的输出：**

- 两次熊市的执行暴露、期间主损失与回撤：无变化（期间止于 2009-03-09）。
- 转绿延迟、R、半山腰转绿与三类件数：两个版本都无变化。
- v1.3 的固定延迟校准：汇总与逐事件明细无变化；事件表里最后两个事件的“下一事件 T0”一列在截止日标签下为空（开发期标签下分别是 2009-10-02 与 2009-10-30），这一列只在固定延迟的执行日不早于下一事件 T0 时才起作用。

**不受影响的：** 不读取标签的信号、执行暴露与价格收益模拟净值（`../extended_nav/`）；使用截止日内标签的失败路径分析（`../failure_path/`）。

## 核对

- 原标签下的重算与已入库的旧输出逐格相同：v1.3 的 `p0_summary.csv`、`reference_rows.csv`、`p0_exit_costs.csv`、`fixed_delay_summary.csv`；v1.4 的 `price_only_summary.csv`、`reference_rows.csv`、`bear_markets.csv`。
- 在既有线性口径、日期轴与暴露不变的条件下，逐区间的局部调整之和等于汇总的变化（三个价格分项、主损失、T；绝对误差上限 1e-10）：26 个对象全部一致，最大的差约 1.2e-26。不一致时程序报错停下、不写出结果。
- T 的局部推算用线性口径：T = L − [ē·L_G + (1−ē)·L_R]，ē 不变，所以 ΔT = ΔL − ē·ΔL_G − (1−ē)·ΔL_R。

## 文件

| 文件 | 内容 |
| --- | --- |
| `标签影响量化报告.md` | 两个版本各自的差异区间、各对象的变化、与参照行的比较、排序、文字结论、其余输出与核对 |
| `label_differences.csv` | 全部归类不同的资产区间 |
| `objects.csv` | 每个对象的五个分项、主损失、T、平均暴露与同暴露基准：原值、截止日标签下的值、差值（完整精度） |
| `local_adjustments.csv` | 逐对象、逐资产、逐分项的局部调整 |
| `reconciliation.csv` | 局部调整之和与汇总变化的五项之差 |
| `comparisons.csv` | 九组设定 × 四条参照行 × 主损失与 T 的差值与比较方向 |
| `rankings.csv` | 九组设定按主损失、按 T 的排序 |
| `run_meta.json` | 代码提交与输入文件的 SHA-256 |
| `output_hashes.json` | 各文件的 SHA-256（命令写出的字节） |

## 复算

```
uv run market-risk wavewarn v14-label-cutoff-impact
```

命令在输出目录已存在时拒绝覆盖；复算前先把本目录整体改名。`run_meta.json` 记有生成时的代码提交，会随仓库状态不同而不同。
