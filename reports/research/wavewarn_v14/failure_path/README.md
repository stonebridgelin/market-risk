# 失败路径分析（T2，描述性）

本报告仅使用各窗口授权截止日以内的数据；只作描述，不改变模型规则、参数、选定设定与γ；不构成任何机制的选择依据，机制选择另由负责人裁决。

v1.4 继续暂停。本目录不重跑、不改写任何已入库的评价输出；各对象按同一本账列出，不作比较选优；两个窗口的输入与环境不同，一个窗口的结论不得套用到另一个窗口。

**复核范围。** 开发期的收益区间数、非绿段、全窗口 Σd、ln(净值比)，以及逐段起止日、段长与 D，已由产品经理与复核者分别从已入库逐日明细独立复算，结果一致；复核未审计整条信号生成链，未运行项目测试，未独立重建迁移窗口的信号。

## 口径

全部口径写在两份报告的“口径”一节，这里只列要点：

- 区间 j 为第 j 日收盘到第 j+1 日收盘。R_{a,j} = C_{a,j+1} ÷ C_{a,j} − 1；R_j^满仓 = ½(R_{SPX,j} + R_{QQQ,j})；R_j^策略 = e_j·R_j^满仓，e_j = x(S_{j−1})（绿 1、黄 0.5、红 0，由前一日的信号决定）；d_j = ln(1 + R_j^策略) − ln(1 + R_j^满仓)。
- 价格收益模拟口径：每日收盘按总暴露、两资产各半再平衡，现金收益为 0，不含分红与费用。任何 1 + R 不大于 0 时程序报错停下。
- 非绿执行段按执行日记录，段长按收益区间数。D 可以相加，exp(D) − 1 不可相加。
- 按结果的三类用 0.0001 的报告中性带；“接近零”不表示结果严格相同，也不表示差异只来自舍入；汇总一律用原始 D。“改善”只指相对满仓的对数收益差为正。
- 短段为段长不超过 5 个收益区间的段，其余为长段。每区间平均 d（基点）= ΣD ÷ 区间数 × 10000；均值只作描述，不是显著性检验。
- 通道同时出现统计按信号日 j−1 的通道状态，按通道是否激活划分，不要求各层输出红灯；跨两层及以上有通道激活的写作“多层同时激活、系统处于非绿”。“系统保持”只作描述，不表示这种保持合理。本统计可以定位拖累发生在哪里，不能识别是哪一层造成的；没有做逐通道的反事实回测。
- 启动方式与事件位置的汇总按启动特征分组，统计完整执行段的结果；不是启动动作的因果效果，也不是对应事件阶段的逐日结果。
- 合并事件：P 取成员最早的 `peak_date`，T0 取最早的 `t0_date`，Tr 取最晚的 `trough_date`，End 取最晚的 `end_date`；任一成员右截尾则合并事件右截尾、End 留空。
- 市场环境标签只作描述，不进入任何信号与选择；平淡年不等同于震荡市。迁移评估窗口中的 2009 年为“完整年度分类不可得”。
- 分类只作描述，不是因果证明。案例段是看过结果之后选出的，不代表典型行情。

## 补充规格（2026-10-01 审核后裁决）

1. **窗口首日启动。** 窗口第一个计入区间即为非绿，而窗口前最后一个执行灯色是绿灯的段，不属于“窗口开始前已启动”：该段在窗口第一个区间启动，“左截断”记“否”，另标“窗口首日启动”（`segments.csv` 的最后一列），并按窗口第一个区间的执行灯色正常归入 (a)(b)(c) 三类之一。“左截断”只用于确实在窗口前已启动的段。
2. **部分资产尾段未定。** 段的起始执行日先按合并事件匹配（另一资产若有正在发生的事件，合并事件已经匹配，按该事件归类）；没有任何事件匹配时，两个资产都处于尾段未定归“事件外（尾段未定）”，只有一个资产处于尾段未定归“事件外（部分资产尾段未定）”。
3. 除这两种情形外，规格未写明的情形仍保持“遇到即报错停下”。

两条规则都有构造数据测试。两个窗口的实际数据里都没有出现这两种情形：全部对象都没有左截断、窗口首日启动或未闭合的段；迁移评估里归入“事件外（尾段未定）”的 1 个段，其起始日在两个资产里都是尾段未定。

另有一处与标签轴有关的处理没有变：合并事件的高点在标签日期轴最前面的 20 个交易日之内时，“高点前第 20 个交易日”取日期轴的第一天；这只涉及 1990 年 1 月的事件，在两个窗口之外。

## 两个窗口的加注各自成立

报告里的加注都由程序按本窗口的数字写出，不把一个窗口的结论写进另一个窗口：

- **按段长。** 开发期（选定设定）：长段贡献了主要累计拖累；短段占用时间少，但单位区间的平均拖累更大（短段 51 个区间、ΣD = −0.090101、每区间 −17.7 基点；长段 783 个区间、ΣD = −0.552559、每区间 −7.1 基点）。迁移评估（纯价格版本）：短段合计为负，单位区间的平均拖累为 −9.2 基点；长段合计为正（132 个区间、ΣD = −0.121018；1461 个区间、ΣD = +0.495298）。
- **通道同时出现统计。** 开发期“只有回调层”为正、“只有趋势层”为负；迁移评估正好相反，“多层同时激活、系统处于非绿”的方向也与开发期不同。迁移评估的报告逐一列出了方向不同的三类，并注明不作横向比较。

## 验收

- **三项对账**（float64，绝对误差不超过 1e-10）：两个窗口、全部对象都满足，最大的差约 4e-15。任何一项不满足时程序报错停下、不写出结果。
- **一致性检查**（各对象的状态序列由现有纯函数重新生成，与已入库输出重叠的部分必须一致）：
  - 开发期：修正后的 v1.4 与 200 日均线的日期、信号灯色、系统执行灯色、收盘价（v1.4 另加激活通道）与已入库的修正后逐日明细逐行一致（每个对象、每个资产 1763 行）；带缓冲带的 200 日均线的平均暴露与计费切换次数（18 次）与已入库参照行一致。
  - 迁移评估：重新生成的状态经现有净值函数得到的逐日净值（12 位小数）与已入库的 `extended_nav/nav_daily.csv.gz` 逐行、逐列相同（2533 行、28 列）。
- **迁移评估的标签**：结束日不晚于 2009-09-30 的 171 个单资产事件与 102 个合并事件，P、T0、Tr、End 及成员与开发期标签逐个相同。
- **与审核版本的逐字节比对**（本次只改报告文字、汇总列与两条补充规则）：
  - `intervals.csv`：把新标签“多层同时激活、系统处于非绿”换回旧标签“多层同时”后，与审核版本逐字节相同；差异只有这一个标签（开发期 553 行、迁移评估 643 行）。
  - `segments.csv`：去掉新增的最后一列“窗口首日启动”后，与审核版本逐字节相同；新增列全部为“否”。
  - 其余有差异的文件：`classification_summary.csv`、`event_position_summary.csv`（列名与新增列、按段长一组）、`channel_cooccurrence.csv`（类别改名）、`失败路径分析报告.md`、`output_hashes.json`，以及记有生成时代码提交的 `labels/label_meta.json`。`environment_summary.csv`、`reconciliation.csv`、`case_periods.csv`、`merged_events.csv`、`consistency_checks.json` 与三个标签文件没有变化。

## 开发期标签里跨过 2009-09-30 的事件

开发期标签里有一个 SPX 事件（高点 2009-09-22，T0 与低点 2009-10-02，结束日 2009-10-14）跨过迁移评估的截止日。在按 2009-09-30 截止生成的标签里它不是事件：截止日时仍在寻峰，SPX 自 2009-09-22 起为“尾段（寻峰）”未定区间。迁移评估部分按生成结果处理。

此前 v1.3、v1.4 补充历史的损失计算用的是开发期标签。它对旧补充历史的影响已另行量化，见 `../label_cutoff_impact/`；本目录使用截止日内的标签，不受影响。

## superseded/

`superseded/2026-10-01_审核版本/` 是产品经理与复核者审核的那一版输出，原样保留。被取代的原因：措辞与汇总列按审核意见收紧，加入两条补充规格，逐区间账本改为压缩入库；段账本与逐区间账本的内容没有变（见上面的逐字节比对）。

## 复算

```
uv run market-risk wavewarn v14-failure-path
```

命令在输出目录已存在时拒绝覆盖；复算前先把本目录整体改名，再比较各子目录的 `output_hashes.json`。`labels/label_meta.json` 里记有生成时的代码提交与工作区是否有未提交改动，这一个文件会随复算时的仓库状态不同而不同，其余文件逐字节相同。约 2 分钟。
