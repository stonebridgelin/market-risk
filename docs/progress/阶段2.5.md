# 阶段2.5：TradingView 导入与使用

## 完成内容
### 第1步：读取与校验（提交 `94441ce`）
- `data/tradingview.py`：文件名解析（`INDEX_S5FI, 1D.csv` → `INDEX:S5FI`）；ISO 时间取偏移下的本地日期、UNIX 时间戳按标的时区换算（不统一转 UTC）；指标列加 `extra_` 前缀保存。
- 校验：日期重复/顺序、known_values（含"疑似日期偏移"）、不完整K线、NYSE 交易日、数值范围、历史完整性、sha256 防改动；多次导出重叠日期不一致时报错且不覆盖。
- 命令：`tv import`（汇总表 + 详细说明 + 结论）、`tv validate`、`tv list`。

### 第6节：在评分中的使用
- 广度读取顺序（SPEC 6.5）：先 TradingView 清洗结果 `S5FI.csv`、`S5TW.csv`，再手工 `breadth.csv`；同日不一致时报告并以 TradingView 为准（只报告基准日前15天内的差异）；prompt 的"数据说明"写明每个读数的来源。
- OAS 长历史（SPEC 6.3）：`oas.long_history_source`（默认 `none`）；为 `tradingview` 时只有 FRED API 取不到的日期（早于 FRED 第一个观测）才用 TradingView 数据，并在 `data_notes` 注明。
- `tv compare --symbol X` → `reports/tradingview_compare_<X>.md`；`tv crosscheck` → `reports/tradingview_crosscheck.md`。接口来源与容差登记在 `symbols.yaml`（`api_source`、`tolerance`）。
- `symbols.yaml` 登记 crosscheck 标的：SPY、QQQ、RSP、HYG、LQD、VIX、BAMLH0A0HYM2、DGS10，以及 reference 的 US10Y；ETF、VIX、OAS、DGS10 的 known_values 来自截图读数与 SOP 附录A。
- 导出文件的交易所前缀与登记不同时（如 `BATS_SPY`），按代码部分唯一匹配并注明。
- FRED ICE 系列的月末周末观测在导入校验中作为说明，不作警告。
