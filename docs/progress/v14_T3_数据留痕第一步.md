## 二、做了什么

1. **字段**（规格第 1 条）：每条记录 26 个字段，逐项对应规格——唯一记录编号、指标代码、交易日、原始值与单位、口径、精度、规范化值、来源、取得方式、首次取得时间（美东）、录入时间、录入人、是否迟到、来源发布时间、原始快照路径与 SHA-256、数据与代码版本、修订关系、人工修正的原值、修正值与证据、历史补录标记。确认人与确认时间在单独的确认记录里。字段表见 `docs/research/数据留痕设计说明.md` 第 3 节。
2. **预留**（第 2 条）：`signal_input_links` 表（信号标识、记录编号、备注）与对应的来源文件路径；本批不写入、不接入信号计算。
3. **历史补录**（第 3 条）：首次取得时间无法证明时留空并必须标“历史补录”；程序不用交易日或录入时间去填。
4. **入口**（第 4 条）：`services.provenance_add / provenance_revise / provenance_confirm / provenance_list / provenance_verify_snapshots`，命令 `market-risk provenance add / revise / confirm / list / verify-snapshots`。第一批覆盖 S5FI、S5TW、NDTW。迁移 `0008_provenance.py` 按既有方式新增，没有修改已有迁移；`storage/schema.py` 同步；`db/sql/` 由命令重新导出。
5. **测试**（第 5 条，10 个）：修订不覆盖原记录（文件只追加一行、原行逐字节不变）；发布时间无法核实时为空；历史补录的标记；迟到判断的边界（恰为 18:30:00 不算，18:30:01 算，含夏令时与冬令时的换算）；规范化值与原始值并存；原始快照哈希核对（改一个字节与删除文件都能查出）；另有确认与自确认、数据库由文件重建、配置与编号、以及“评分、波段预警、研究、数据构建都不导入留痕模块”的检查。
6. **设计说明**（第 6 条）：`docs/research/数据留痕设计说明.md`，写明字段、约束与“本批不接入研究计算”的边界。`docs/STORAGE.md` 补了目录与三张表的说明。

裁决 12—17 的落实：严格晚于美东 18:30:00 才算迟到；以 `data/manual/provenance/` 下只追加的文件为准、数据库由 `rebuild-db` 重建；录入与确认分两条命令，不强制确认人不同，相同时自动标“自确认”并在查询里显示；原始值原样保存，规范化值为 0—100 的 `Numeric`，超出范围拒绝；记录 git 提交号与“未提交改动”，数据版本没有就留空；本批只建能力与测试，不批量导入。
