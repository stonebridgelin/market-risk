### 只能运行一次的保护：测试覆盖的拒绝情形（临时 git 仓库，没有行情数据）

1. 锁定之后又提交了别的文件（HEAD 相对于代码提交号的差异不止锁定记录）。
2. 记录里的提交号是更早的提交，或在仓库中不存在。
3. 已跟踪文件有未提交的改动；有未跟踪的文件。
4. 某份规格或配置的 SHA-256 与记录不一致；记录缺少某份配置的哈希。
5. 记录是草稿；选定设定不是 K=5、θ_P=2.5%；随机种子与配置不一致。
6. 找不到 git（提示把 `C:\Execute\Git\bin` 加入 PATH 或在配置中指定）。
7. 输出目录已存在：在核对锁定记录之前就拒绝。
8. 核对通过后，运行一开始就写入 `lock_record.json`（记录路径、SHA-256、代码提交号、HEAD）。测试用的临时仓库没有数据，随后在读取输入时失败；此时再次运行被拒绝。

另有一项通过情形：格式正确、单独提交的记录核对通过，并返回记录的 SHA-256。

## 七、实现中的口径说明

1. **锁定记录中的 SHA-256** 取各文件在 HEAD 中已提交的内容（LF 换行），不取工作区文件；本机 git 检出时会把部分文件的换行转成 CRLF，按工作区文件算会对不上。
2. **第三份配置** `config/wavewarn_v14_validation.yaml` 也列入锁定记录的“配置 SHA-256”一栏，由验证期命令核对。
3. **前后两半与删除置零日期**的重抽样用主设定的区块长度 20 与种子 20260929（与 v1.2.1 的既有实现一致）；区块 10、40 用各自登记的种子。
4. **逐事件剔除**只重算 Σd 并标出是否变号，不重新做重抽样（同 v1.2.1 规格）。
5. **验证期的事件账规则**用此前实现的 `validation_scope_rule`：事件按 P ≥ 2017-01-03 归属，高点前 20 天的灯色可落在 2016 年，但不早于 τ。
6. **演练的锁定记录信息**取自草稿：只核对选定设定、随机种子与重抽样次数，不做 git 核对；报告开头标明是草稿。
