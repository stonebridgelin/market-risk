## 3. 发现的问题

### 3.1 必须修正（第二部分重新生成报告前）

1. **报告中有写死的结论文字。** `render_review` 固定输出"未添加任何实际 correct 条目"，以及针对具体日期的说明（SPY 2012-01-20、QQQ 2010-11-26、RSP 2016-06-24、SPY 2015-08-21/24）。这些文字不随计算结果变化；第二部分添加 SPY 2009-07-16 的修正条目后，报告会自相矛盾。
   修正：修正条目列表从 data_decisions.yaml 读取后生成；逐日说明由计算结果生成（例如"Yahoo 残差反向回归但 z=5.74<6"），不再写死日期。

### 3.2 建议修正

1. **data build 遇到无效裁定时直接抛出异常栈。** `services.data_build` 只捕获 DataFetchError；YAML 中 correct 条目有误（ConfigError）或日期不存在（ValueError、MarketDataError）时，CLI 显示 Python 异常栈而不是"错误：…"。`score` 在录入广度后也会调用 data build，同样受影响。
   修正：在 services 中把这几类异常转为 ServiceError，补测试。
2. **没有检查争议日或次日本身是否为除息日。** 不复权收盘价在除息日会下跌一个分红额，如果争议日或次日恰是除息日，残差会带入分红，可能造成误判。目前 10 个日期都不是除息日（已核对），不影响现有结论。
   修正：遇到这种情况判"无法判定"并注明原因，补测试。
3. **隔离测试只查直接 import。** 建议增加传递依赖检查：在子进程中导入 pipeline、scoring、snapshot、market，确认 `sys.modules` 中没有 price_review 相关模块。第四部分新增回测引擎后，也要把回测模块纳入这项检查。
4. **把迁移号断言移出 `test_migration_0003_keeps_data`**，改为单独的测试"最新迁移号等于 migrations/versions 中最大的版本"。

- 审查用 ROUND_HALF_UP 与评分用 round() 不一致，但 2007 年以后 ETF 价格全部为整分，不影响结果。
