## 六、需要负责人决定的事项（阻塞“验证期工程修改”）

下面六问都落在会被锁定核对或决定报告自动结论的地方，登记没有写明，我没有自行假设。每问附建议做法。

**1. 区块长度 60、120 的随机种子。** 登记的种子只有 20（20260929）、10（20260910）、40（20260940）三个。
建议：沿用“202609 + 区块长度”的写法，60 用 `20260960`，120 用 `202609120`（九位数；锁定核对里识别种子的规则相应放宽）。前后两半仍只在区块 20 上做。理由：与现有三个种子的规律一致，不需要另行解释。

**2. F.1 的“样本量不满足方法要求”与 E 的“长区块下注明估计可能不稳定”各用什么界线。** 登记没有给数值。
建议：第一层的无效条件取 n ÷ b < 2（正式口径 b=20，即 n < 40）；E 的“估计可能不稳定”对区块 60、120 一律注明，并报告 n 与 n ÷ b（开发期 1762 个区间时为 29.4、14.7）。某一敏感性自身出现第一层的无效情形时，该行单独标“计算无效”，不参与稳定性降级，也不使主结论无效。

**3. 判定句与 F 的分类措辞如何并存。** 确认事项第 2 条要求判定句保留 v1.4 修订登记原文（p < 0.05 写“……带来了额外的择时价值”，否则写“未证明优于200日均线”）；F.2 又给了 A 至 D 四类各自的措辞。两处在 A 类以外不会矛盾，但有三种情形需要定：(a) A 类被降为“证据不稳定”或带统计警示时，是否还写“带来了额外的择时价值”；(b) p < 0.05 而 θ̂ ≥ 0（会触发 W3）时，原规则字面上会写“带来了额外的择时价值”；(c) 第一层无效时是否两句都不写。
建议：报告的自动结论以 F 为准；v1.4 修订登记的判定句作为单独一行并列——仅当第二层为 A 时写前一句（后面照附降级与警示标注），B、C、D 写后一句，第一层无效时两句都不写、只输出“计算无效，需核验”。

**4. 第一层“计算无效”时，正式验证期运行算作完成还是失败。** F.1 说“只输出‘计算无效，需核验’”，按字面是把报告与全部原始数值写入正式输出目录（此后命令拒绝再次运行）；而补充登记 C 的失败处理是不创建正式目录、允许修复工程代码后重新锁定再跑。同一种情形（例如两模型日期不一致）现在的程序是直接报错，走的是 C。
建议：程序能算出统计量的情形（NaN、p 越界、区间倒置、重抽样次数不符、退化、样本量不足）照 F.1 写出正式输出并标“计算无效，需核验”；根本无法进入计算的情形（日期或索引不一致等程序异常）仍按 C 记为失败的运行、不创建正式目录。理由：前一类保留了全部原始数值供核验，后一类没有可核验的数值。

**5. 是否现在重跑开发期演练，以及演练所核对的锁定记录草稿怎么办。** 第三节第 2 条要求带缓冲带的均线“开发期与验证期都运行”，F 的自动判定与净值并列也只有重跑演练才能在开发期上看到；但本批没有写“重新演练”，同时锁定记录草稿的更新被列为暂缓。新增的种子（第 1 问）与新增配置的哈希一旦纳入锁定核对，未更新的草稿就通不过演练命令的核对。
