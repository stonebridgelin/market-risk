## 1. 项目目标

用程序替代截图，完成美股大盘风险评分的数据准备、机械计算和 prompt 生成：

1. 输入一个基准日（以及手工录入的 S5FI、S5TW 读数），自动：
   - 计算 T−5、T−20、20日窗口、OAS 的 O1/O6（两套口径）、三环节查询起点、结果窗口；
   - 通过接口下载 SPY、QQQ、RSP、HYG、LQD 日线，VIX，OAS，财政部10年期收益率；
   - 计算 MA5/MA10/MA20/MA30/MA50/MA200（简单均线，基于不复权收盘价）；
   - 按 SOP 第7节计算 v2-M 与 v3-R1 的五个维度分数、总分、阶段、"大盘明确恶化"证据链；
   - 完整遍历三环节（v2-M）；
   - 输出原始数据 CSV、结果 JSON、可直接粘贴进 ChatGPT 的 prompt（Markdown）。
2. 用已完成的4个历史样本做回归测试，验证程序计算值与截图读数一致。
3. 为以后接入 LangChain Agent 做准备：核心逻辑写成输入输出清晰的纯函数，不依赖全局状态。**本阶段不引入 LangChain。**

## 4. 核心数据模型（`models.py`）

至少包含以下结构（字段可补充，不可删减）：

- `DateReferences`：`base_date`、`t_minus_5`、`t_minus_20`、`window_start`、`window_end`、`oas_o1`、`oas_o6_v3r1`、`oas_o6_v2m`、`oas_o1_to_o6_sequence`（O1往前的债市营业日列表）、`three_segment_query_start`（T−45）、`outcome_window_start`、`outcome_window_end`、`stock_holidays_in_window`、`bond_holidays_in_window`、`is_early_close`。
- `EtfSnapshot`：`symbol`、`close`、`ma5`、`ma10`、`ma20`、`ma30`、`ma50`、`ma200`、`closes`（截至基准日的逐日收盘价序列）。
- `BreadthReading`：`date`、`s5fi`、`s5tw`（百分数，如 58.44 表示 58.44%）、`source`（"manual"）。
- `MarketSnapshot`：`refs`、`etfs`（SPY/QQQ/RSP）、`breadth`、`breadth_t5`（可为 None）、`vix`、`vix_t5`、`yields`（窗口内逐日财政部数值，含 T−20）、`y`、`h`、`h_date`、`y_t20`、`oas_o1`、`oas_o6_v2m`、`oas_o6_v3r1`、`hyg_lqd`、`data_notes`（数据问题说明列表）。
- `DimensionScore`：`name`、`score`（0/1/2 或 None 表示待补）、`possible_scores`（待补时可能的取值集合）、`triggered_conditions`（触发了哪一条）、`calculation`（计算过程文字）、`pending_reason`。
- `ScoreResult`：`version`（"v2-M" / "v3-R1"）、五个 `DimensionScore`、`total`（确定时）或 `total_range`（有待补时）、`stage`、`clear_deterioration`（证据链逐项：是/否/无法核验）。
- `ThreeSegmentTrace`：每只 ETF、每个候选 d1 的 `d1_close`、`lc`、`lc_date`、`step1`、合格的 `d2` 列表、`step3`、`completed`。

所有百分比在内部统一用"百分数"表示（4.11 表示 4.11%，40.15 表示 40.15%），避免小数与百分数混用。计算 bp 时乘以100。

## 5. 业务规则（程序化表述）

### 5.1 时点口径（SOP 第3节）

- 分析时点：基准日美东18:30之后。
- ETF 收盘价与均线：基准日常规交易收盘价；提前收盘日以提前收盘价为准。**使用不复权收盘价**：yfinance 调用时设 `auto_adjust=False`，取 `Close` 列，**不得使用 `Adj Close`**（`Adj Close` 按基准日之后的股息调整历史价格，属于未来信息）。
- VIX：FRED `VIXCLS` 基准日数值，与 T−5 数值比较。
- 10年期收益率：财政部每日 Par Yield Curve 的 `10 Yr` 列。回测模式直接使用；每日模式若基准日数值尚未发布，利率维度记待补，**不得用前一日或第三方数值替代**。
- OAS：FRED `BAMLH0A0HYM2`。ICE 数据通常次日上午发布，所以 O1 是基准日之前最近一个债市营业日的观测，**基准日当天的观测不得使用**。

### 5.2 日期计算（SOP 第6节）

- **股票交易日**：用 `pandas-market-calendars` 的 NYSE 日历；提前收盘日也由它识别。
- **债市营业日**：以财政部收益率数据中实际存在的日期为准（工作日没有财政部数据即视为债市休市）。同时与 `config/holidays.yaml` 核对，两者不一致时在 `data_notes` 中报告，不自动修正。
- T−5、T−20：按股票交易日往前数。
- 20日窗口：T−19 至 T（共20个股票交易日）。利率窗口内若有债市休市日，观测数少于20，不插值、不替代。
- O1：基准日之前（不含基准日）最近一个债市营业日。
- O6（v3-R1）：O1 之前第5个债市营业日；月末周末观测不计入；若 FRED 在该日没有观测，信用维度记待补。
- O6（v2-M）：按 FRED 实际返回的观测列表，从 O1 往前数第5个观测（月末周末观测计入）。
- 两种 O6 不同时，在 `data_notes` 中说明原因。
- 三环节查询起点：T−45（按股票交易日）。
- 结果窗口：基准日之后第1至第20个股票交易日（只计算日期，不下载、不计算结果窗口内的任何行情）。

### 5.3 共同规则（SOP 7.1）

- 每个维度先判2分，再判0分，其余有效组合为1分；条件重叠取较高分。
- 必要数据缺失记"待补"（score=None），不得记0分。
- 缺失字段的所有可能取值都不改变结果时，给确定分数，并在 `calculation` 中写明理由。实现方式（2026-09-26 修订）：
  - 缺失值的取值范围：广度 0–100，VIX 0.01–200，收益率 −5% 至 30%，OAS 0–50（均为两位小数）。
  - 按**临界点**取值，不按固定步长取样：各门槛值（含由其他已知字段推出的门槛，如 V5×1.3、O6+0.20、T−20 的 y+0.25、H），门槛两侧的相邻值（两位小数下的 ±0.01；门槛不是两位小数时取其两侧最近的两位小数值），以及范围两端。
  - 其他已知字段一并代入规则计算（例如 F 缺失、W 已知时，L=min(F,W) 不超过 W）。
  - 所有候选组合的结果相同则给确定分数，否则记待补并列出可能取值。
- OAS 按 FRED 公布的两位小数计算；所有等号边界严格按规则原文（`≥`、`≤`、`<`）实现。
- **精度（2026-09-26 修订）**：
  - 原始数据按公布精度读取（价格、VIX、OAS、收益率、广度均为两位小数），转为 Decimal，以消除浮点误差。
  - 派生值（均线、g、ΔOAS、Δy、v2-M 广度条件中的"20日最高收盘价×0.98"等）用 Decimal 精确计算，**不取整**，直接与门槛比较；只在展示时保留两位。
  - 理由：先取整等于把 g≥30% 改成 g≥29.995%，属于修改规则。
- 总分：0–2 早期信号；3–5 中期确认信号；6–10 高风险。
- 有待补时：输出已确定分数、待补维度、总分范围；范围跨越阶段时不给唯一阶段。
- 大盘明确恶化：价格=2 且 广度=2 且（信用=2 或 VIX=2）。证据链逐项输出"是/否/无法核验"。

### 5.4 规则A：v2-M（SOP 7.2）

**价格**
- 2分（任一）：(a) 至少两只收盘价 < 各自 MA50；(b) 任一只在基准日完成三环节；(c) SPY 收盘价 < MA200。
- 0分：三只收盘价均 ≥ 各自 MA50，且最多一只 < 各自 MA20。
- 1分：其余。

**三环节机械定义**（对每只 ETF 分别判断）：
- 候选 d1：位于基准日之前的交易日范围内（范围口径见5.6节），且至少早于基准日2个交易日。
- Lc：d1 之前20个交易日（d1−20 至 d1−1）的最低收盘价，同时记录其日期。
- 第一步：d1 收盘价 < Lc。
- 第二步：存在 d1 与基准日之间（不含两端）的日期 d2，满足 d1 收盘价 < d2 收盘价 ≤ Lc。
- 第三步：基准日收盘价 < d1 收盘价。
- 三步都成立的 d1 存在即为完成。已完成的历史三环节不保留。
- 输出完整遍历记录（`ThreeSegmentTrace`），供人工复查。

**广度**（F=S5FI，W=S5TW，L=min(F,W)，F5/W5 为 T−5 读数）
- 2分（任一）：(a) L<40，且 F<F5、W<W5；(b) F<40，且 SPY 收盘价 ≥ 20日窗口内最高收盘价 × 0.98。
- 0分：L≥50。
- 1分：其余。

**VIX**（g = V/V5 − 1）
- 2分：V≥25；或 V≥20 且 g≥30%。
- 0分：V<18 且 g<20%。
- 1分：其余。

**利率**（y 为基准日财政部数值，H 为20日窗口内最高值，Δy = 100×(y − T−20 的 y)）
- 2分：y=H 且 Δy≥25。
- 0分：y<H。
- 1分：y=H 且 Δy<25。

**信用**（ΔOAS = 100×(O1 − O6)）
- 2分：ΔOAS≥20，或 O1≥4.00。
- 0分：ΔOAS≤5，且 O1<4.00。
- 1分：其余。
- 若 O1 滞后基准日超过1个股票交易日，最高只计1分。

### 5.5 规则B：v3-R1（SOP 7.3）

**价格**
- 2分（任一）：(a) 至少两只同时满足"收盘价 < MA50"与"MA5 < MA50"；(b) SPY 收盘价 < MA200。
- 0分：不满足2分，且三只收盘价均 ≥ 各自 MA50，同时最多一只 < 各自 MA20。
- 1分：其余。三环节不参与计分。

**广度**
- 2分（任一）：(a) L<40，且 F<F5、W<W5；(b) F<40，且 F<F5。
- 0分：L≥50。
- 1分：其余。

**VIX、利率**：与规则A相同。

**信用**
- O1 必须是基准日之前最近一个债市营业日的观测，且在分析时点前已发布；否则记"待补：数据滞后"。
- O6 按5.2节 v3-R1 口径；该日缺失时记待补。
- 2分：ΔOAS≥20，或 O1≥4.00（此时无需 O6）。
- 0分：ΔOAS≤5，且 O1<4.00。
- 1分：其余。

### 5.6 SOP 未写清楚之处的既定口径

1. **三环节候选 d1 是否包含 T−20**：SOP 原文为"位于基准日前20个交易日内"。在 `settings.yaml` 中设开关 `three_segment.d1_includes_t_minus_20`，默认 `true`（候选为 T−20 至 T−2）。**程序同时按两种口径计算**，若结果不同，在输出中醒目标注"三环节结果依赖口径"。
2. **可省略字段**（SOP 4.2）：程序始终尝试获取全部数据；广度 F5/W5 是手工输入，只有在规则需要时才要求录入。具体：L≥50 时不需要；F<40 或 L<40 时需要。需要而缺失时，按5.3节"枚举可能取值"处理，结果不确定则记待补，并在命令行提示需要补录哪一天的读数。
3. ~~OAS 发布时点核验~~ → **OAS 历史修订比对**（2026-09-26 修订，默认开启）：
   - 联网确认：ALFRED 中 `BAMLH0A0HYM2` 的版本日期等于观测日期（例如 2025-11-28 的版本已包含 11-28 的观测），**ALFRED 版本日期不能代表真实发布时间**，无法据此核验"分析时点前已发布"。
   - 发布时点一律按"次日发布"假设处理：O1 为基准日之前的观测，基准日当天的观测不使用。
   - 用 `realtime_start` / `realtime_end` 取基准日版本，与当前版本比对 O1、O6（两个版本口径）的数值；发现修订时在 `data_notes` 报告。
   - 计分使用当前版本；若用基准日版本计分会改变任何维度的分数，停下来交给用户判断，不自动选择。
   - 无法取得版本数据时，在 `data_notes` 中说明，不影响计分。
4. **v2-M 的"O1 滞后"算法**（2026-09-26 确认）：滞后天数 = O1 之后（不含）至基准日（含）之间的股票交易日个数；大于1即滞后，v2-M 信用最高1分，并在 `calculation` 中写明封顶原因。例如基准日 2025-10-14（10-13 债市休市、股市开市），O1 为 10-10，滞后2个交易日，v2-M 封顶1分；v3-R1 的 O1 仍是"基准日之前最近一个债市营业日"，不受影响。这是两个版本应有的区别，不需要修正。
5. **利率数据缺失**（2026-09-26 确认）：
   - T−20 当天债市休市：Δy 缺失，不用相邻日替代。y<H 时直接0分；y=H 时记待补（可能取值 {1,2}）。
   - 基准日本身债市休市、股市开市：y 缺失，利率维度记待补（可能取值 {0,1,2}）。
6. **窗口内并列最高**（2026-09-26 确认）：`h_date` 列出所有并列最高的日期，摘要显示最早一天。基准日的 y 与窗口内更早某天并列最高时属于 y=H，按财政部公布的两位小数比较。
7. **VIX 数据来源与缺失**（2026-09-26 确认）：
   - V 与 V5 均按以下顺序获取：先取 FRED `VIXCLS`；FRED 缺失时改用 Cboe 官方 `VIX_History.csv` 的 `CLOSE` 列（同一官方数值，不算替代），并在 `data_notes` 注明来源。
   - 两个来源都有值但不一致时，在 `data_notes` 报告差异，以 FRED 为准。
   - 两个来源都缺失才记缺失，按5.3节待补枚举处理。
   - 此备用源只用于 VIX。
8. **FRED 缺失值行不算观测**（2026-09-26 确认）：FRED 返回值为 `"."` 的行不是观测。v2-M 的 O1（最新观测）和 O6（从 O1 往前数第5个观测）都只数有数值的行。例：基准日 2025-10-14，若 FRED 在 10-13 返回 `"."`，v2-M 的 O1 为 10-10，不得取 10-13；基准日 2025-10-17，O1=10-16，v2-M 的 O6 为 10-08（跳过 10-13），与 v3-R1 相同。
9. **股市休市、债市开市的日子**（2026-09-26 确认，例：2026-04-03 耶稣受难日，股市休市，债市12:00提前收盘；SIFMA 因当天发布非农数据不建议全天休市）：
   - T−5、T−20、20日窗口、H 的范围只按股票交易日计算；财政部在股市休市日公布的数值不计入利率窗口，并在 `data_notes` 中注明被排除。
   - v3-R1 的 O1/O6 按债市营业日计数，包含这类日子；若 FRED 在该日无 OAS 数值且该日正好是 O6，信用维度记待补，并在 `data_notes` 报告。
   - v2-M 只数有数值的观测（见第8条）。
   - 例：基准日 2026-04-24，20日窗口为 2026-03-27 至 2026-04-24，利率窗口不得包含 04-03 的财政部数值。
10. **FRED 在债市休市日的沿用值**（2026-09-26 确认，方案B）：联网确认 FRED 的 `BAMLH0A0HYM2` 在债市休市日返回沿用值（等于前一个观测），不是 `"."`，例如 2025-09-01（2.84）、10-13（3.18）、11-11（3.02）、11-27（3.00）。
    - v2-M 排除债市休市日（以财政部数据为准）的 OAS 观测，保留月末周末观测。
    - 区分依据：月末周末观测是真实数据，数值通常与前一个观测不同（例如 2025-08-31 为 2.84，08-29 为 2.82）；债市休市日的数值是沿用值，等于前一个观测（例如 2025-09-01 为 2.84，与 08-31 相同）。
    - v3-R1 本来按债市营业日计数，不受影响；O1 同样不得取休市日的数值。
    - 若某个债市休市日的 FRED 数值与前一个观测不同，不自动排除（仍计为观测），在 `data_notes` 中报告，交给用户判断。
    - 例：基准日 2025-10-14，v2-M 的 O1=10-10，滞后2个股票交易日，信用封顶1分；基准日 2025-10-17，v2-M 的 O6=10-08；样本4（2025-11-28）v2-M 的 O1=11-26、O6=11-19；基准日 2025-09-02，09-01 劳动节的沿用值排除，08-31（周日）月末观测计入，v2-M 的 O1=08-31（不滞后），v3-R1 的 O1=08-29。
    - 第8条（`"."` 行不算观测）继续有效。

## 6. 数据获取（`data/`）

### 6.1 通用要求
- 每次下载写入 `data/cache/`，文件名包含数据源、代码、日期范围；同时保存元数据（来源 URL、下载时间、行数）。
- 支持 `--refresh` 强制重新下载；默认优先使用缓存。
- 网络失败时重试3次（指数退避），仍失败则抛出明确的错误信息。
- `snapshot.py` 负责把所有数据**截断到基准日（含）**，并在构建完成后断言：任何序列的最大日期 ≤ 基准日。

### 6.2 ETF 日线（`prices.py`）
- 标的：SPY、QQQ、RSP、HYG、LQD。
- 下载范围：基准日往前至少 420 个自然日（保证 MA200 和三环节有足够数据）至基准日次日（yfinance 的 `end` 参数不含当天）。
- `auto_adjust=False`，只使用 `Close`。
- 均线：对截至基准日（含）的 `Close` 做简单移动平均；数据不足周期时报错，不得计算。
- HYG/LQD：两者收盘价之比，保留4位小数，仅作参考。

### 6.3 FRED（`fred.py`）
- 使用 FRED API（`https://api.stlouisfed.org/fred/series/observations`），参数带 `api_key`、`file_type=json`、`observation_start`、`observation_end`。
- 系列：`VIXCLS`、`BAMLH0A0HYM2`。值为 `"."` 表示缺失，转换为缺失值，不得当作0。
- ALFRED 版本查询见5.6节第3条。
- 备注：自2026年4月起 FRED 只提供 ICE 系列最近三年的观测，更早的日期取不到时要给出明确提示。
- VIX 备用源：Cboe 官方 `VIX_History.csv` 的 `CLOSE` 列，使用规则见5.6节第7条。
- OAS 长历史（`docs/TRADINGVIEW.md` 第6.2节）：`settings.yaml` 中 `oas.long_history_source` 取值 `none`（默认）或 `tradingview`。开启前必须先运行 `tv compare --symbol BAMLH0A0HYM2`，重叠日期数值须完全一致（两位小数），由用户决定是否开启。开启后只有 FRED API 取不到的日期才使用 TradingView 导出数据，并在 `data_notes` 中注明来源。

### 6.4 财政部收益率（`treasury.py`）
- 数据源：财政部 Daily Treasury Par Yield Curve Rates 的年度 CSV 下载（在 home.treasury.gov 的 Interest Rate Statistics 页面，按年份导出 CSV）。请先确认当前可用的下载 URL 格式，并在代码注释中写明。
- 取 `Date` 与 `10 Yr` 两列。
- 备用源：FRED `DGS10`（数值与财政部相同）。主源失败时使用备用源，并在 `data_notes` 中标注。
- 用 `docs/SOP.md` 附录A的2025年8月至12月数值做一致性测试。

### 6.5 广度（`breadth.py`）
- 读取顺序（`docs/TRADINGVIEW.md` 第6.1节）：
  1. TradingView 导出数据（`data/processed/tradingview/S5FI.csv`、`S5TW.csv`）；
  2. 手工录入的 `data/manual/breadth.csv`（导出日之后的新日期）。
  两个来源在同一日期都有数值但不一致时，在 `data_notes` 中报告差异，以 TradingView 导出数据为准。
- 没有免费接口；TradingView 未覆盖的日期采用手工录入：`data/manual/breadth.csv`，列为 `date,s5fi,s5tw,note`。
- 命令行也可直接传入（见第8节），传入值会同时写入该 CSV。
- 读取时校验：数值在 0–100 之间；同一日期不能有两条记录。

## 8. 命令行（`cli.py`，typer）

```
uv run market-risk dates   --date 2025-11-28
uv run market-risk fetch   --date 2025-11-28 [--refresh]
```
