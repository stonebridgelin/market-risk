## 1. 目标与边界

**目标**：每天收盘后，用固定、可机械执行的规则，客观判断美股大盘内部结构是否在变差，避免凭感觉或情绪做判断。

**边界**：
- 只判断大盘风险状态，**不提供仓位建议**，不预测点位，不承诺准确性。
- 分数是规则标签，**不是经过校准的概率**。"风险显著上升"不代表统计显著，也不代表接下来一定下跌。
- 由地缘冲突等外部事件引发的下跌，任何基于市场内部数据的规则都无法事先预知。
- 确认型框架本身偏滞后，强项是防止误报，不是抢先预警。

**三类框架的分工**（本手册只覆盖第一类）：

| 框架 | 作用 | 文件 |
|---|---|---|
| 确认型风险评分（本手册） | 判断大盘是否进入风险上升或明确恶化 | 本文件 |
| 过热预警 | 上升趋势中捕捉狂热，包括"指数高位、广度背离" | 美股顶底信号分析模板.md（模板一） |
| 底部信号 | 下跌中捕捉恐慌见底 | 美股顶底信号分析模板.md（模板二） |

## 2. 角色分工与工作流程

### 2.1 三方分工

| 角色 | 职责 |
|---|---|
| 用户 | 从交易软件、TradingView、FRED 截图或查询数据 |
| Claude | 核对数据是否合规，补充财政部官方数据，组装完整 prompt |
| ChatGPT | 按规则打分，输出计算过程与结果 |

Tiger AI 的问答可以作为背景信息（新闻、讲话、经济数据日历），**不参与计分**。

### 2.2 每日流程（前瞻使用）

1. 基准日美东时间18:30之后，用户收集第4节列出的数据。
2. 交给 Claude 核对：日期、均线数值、未来信息、缺失项。
3. Claude 按第11.2节模板生成 prompt。
4. 交给 ChatGPT，同时计算 v2-M 与 v3-R1。
5. Claude 按第12节核查结果，记录到日志。
6. 20个交易日后，由程序计算结果标签（第9.3节，`market-risk outcome compute`），用户抽查核对；不回传给 ChatGPT。

### 2.3 历史回测流程

1. 按第9.2节固定规则确定基准日，不看行情挑日期。
2. 用户截图，所有图表的最后一根K线必须是基准日。
3. Claude 核对，补充财政部官方数据，按第11.1节模板生成 prompt。
4. ChatGPT 打分；Claude 核查；更新第10节记录表。
5. 结果标签由程序计算，用户抽查核对；只记录结果，不发给 ChatGPT。

## 3. 时点口径（用户已于2026-09-26决定：收盘后分析）

| 项目 | 口径 |
|---|---|
| 分析时点 | 基准日美东18:30之后；只用该时点已公布、且描述基准日或更早状态的数据 |

## 5. 截图检查清单（防止未来信息泄露）

Claude 收到截图后逐项检查：

1. **日期**：十字光标或顶部日期是否是基准日。周线显示的是该周起始日（例如周一），属正常。
2. **均线数值是否对应基准日**：顶部均线栏可能显示的是图表最右端某天的数值，而不是十字光标那一天。检查方法：在图上读出MA50、MA200线在十字光标处的高度，与顶部数值比对。曾出现过顶部 MA5 显示661.92、实际应为687.64的错误。
3. **右侧是否裁干净**：十字光标右侧不能有后续K线、成交量柱或均线延伸。
4. **最新价标记线**：Tiger 的红色水平虚线、TradingView 的青色水平虚线，通常是当前最新值，属于未来信息。无法去除时，在 prompt 中要求忽略；VIX 图因此一律不发。
5. **纵轴范围**：若纵轴上限明显高于可见K线（例如 VIX 图顶部37.93而可见最高仅29），可能是后续数据撑高，不得据此推断。
6. **代码标注**：截图没有显示代码时，发送时注明名称。曾出现把"2025年的SPY周线"误当成"RSP日线"的情况。
7. **OAS截图**：顶部 Observations 显示的日期必须正好是 O1 或 O6；FRED 图上的数据提示框可能遮挡关键日期，O6 必须以文字数值为准。

## 6. 日期计算规则

| 项目 | 定义 |
|---|---|
| 5个交易日前（T−5） | 按美国股市交易日往前数5天 |
| 20个交易日前（T−20） | 按美国股市交易日往前数20天 |
| 20日窗口 | T−19 至 T，共20个交易日 |
| OAS 的 O1 | 基准日之前最近一个**美国债券市场营业日**的观测 |
| OAS 的 O6（v3-R1） | O1 之前第5个债券市场营业日的观测；**月末周末观测不计入** |
| OAS 的 O6（v2-M） | 按 FRED 所列观测顺序从 O1 往前数第5个；月末周末观测也计入 |
| 结果窗口 | 基准日之后第1至第20个交易日 |

**注意**：
- 股市开市、债市休市的日子（例如哥伦布日、退伍军人节）：财政部没有收益率数据，OAS 也没有观测。利率窗口内少一个观测，不插值、不替代。
- FRED 的 ICE 系列在月末落在周末时会出现周末观测（例如曾出现"2026-01-31"周六的数据点）。
- （2026-09-26 补充）FRED 的 OAS 在债市休市日返回的是**沿用值**（等于前一个观测，例如 2025-10-13 为 3.18，与 10-10 相同），不是缺失。
- （2026-09-27 统一规则）债市休市日（以财政部数据缺失为准）的 OAS 观测**一律排除**，v2-M 与 v3-R1 都不计入，不论数值是否与前一观测相同。**例外**：债市休市日恰好是自然月末（例如 2010-05-31、2021-05-31）时视为月末观测：v2-M 计入，v3-R1 不计入。月末周末观测仍按原规则（v2-M 计入，v3-R1 不计入）。详见 `docs/SPEC.md` 5.6 第10条；1997 年以来的清单见 `reports/holiday_calendar_audit.md`。
- （2026-09-27）财政部数据与 SIFMA 常见规则不一致的日期以财政部数据为准：2012-10-30（飓风桑迪）、2018-12-05（老布什国丧日）按债市休市；2010、2012、2015、2021、2023、2026 年的耶稣受难日按债市开市（提前收盘）。见 `config/holidays.yaml`。

## 7. 评分规则全文

### 7.1 共同规则

- 每个维度先判2分，再判0分，其余有效组合为1分；条件重叠取较高分。
- 必要数据缺失或无效记"待补"，不得记0分，不得用其他指标替代。
- 缺失字段的所有可能取值都不改变结果时，可以给确定分数，但必须说明理由。
- OAS 按 FRED 公布的两位小数计算，不推测未公布的小数位；等号边界按规则原文执行。
- 总分0-10：
  - 0-2：早期信号
  - 3-5：中期确认信号，可标注"风险显著上升"，不等于"大盘明确恶化"
  - 6-10：高风险，必须核验证据链
- **大盘明确恶化**：价格=2 且 广度=2 且（信用=2 或 VIX=2），缺一不可。利率单独上升不构成确认。
- 有待补时：列出已确定分数、待补维度、可能的总分范围；范围跨越阶段时不给唯一阶段。
- 证据链逐项写"是 / 否 / 无法核验"。

### 7.2 规则A：v2-M（比较基准，v2 的机械化解释）

**一、价格（0-2）**
- 2分：满足任一：(a) 至少两只收盘价 < 各自MA50；(b) 任一只在基准日完成三环节破位；(c) SPY收盘价 < MA200。
- 三环节机械定义：存在日期 d1，位于 T−20 至 T−2（即基准日之前第20个至第2个交易日，包含 T−20，与下文 Lc"d1 之前20个交易日"的写法一致；2026-09-27 确定）；整理低点 Lc = d1 之前20个交易日的最低收盘价；d1 收盘价 < Lc；存在 d1 与基准日之间的日期 d2，d1 收盘价 < d2 收盘价 ≤ Lc；基准日收盘价 < d1 收盘价。任一 d1 满足即成立。已完成的历史三环节不保留。
- 0分：三只收盘价均 ≥ 各自MA50，且最多一只 < 各自MA20。
- 1分：其余有效组合。

**二、广度（0-2）**，F=S5FI，W=S5TW，L=min(F,W)，F5、W5为5个交易日前读数
- 2分：满足任一：(a) L<40%，且 F<F5、W<W5；(b) F<40%，且SPY收盘价 ≥ 过去20个交易日最高收盘价×0.98。
- 0分：L≥50%。
- 1分：其余有效组合。

**三、VIX（0-2）**，g = V ÷ V5 − 1
- 2分：V≥25；或 V≥20 且 g≥30%。
- 0分：V<18 且 g<20%。
- 1分：其余有效组合。

**四、利率（0-2）**，y为财政部官方数值，H为基准日及之前19个交易日的最高值，Δy = 100×(y − 20个交易日前的y)
- 2分：y=H 且 Δy≥25。
- 0分：y<H。
- 1分：y=H 且 Δy<25。

**五、信用（0-2）**，ΔOAS = 100×(O1 − O6)
- O1为分析时点已发布的最新观测；O6按FRED所列顺序往前数第5个（月末周末观测计入）。
- 2分：ΔOAS≥20，或 O1≥4.00%。
- 0分：ΔOAS≤5，且 O1<4.00%。
- 1分：其余。
- 若 O1 滞后基准日超过1个股票交易日，最高只计1分。

### 7.3 规则B：v3-R1（候选版本）

**一、价格（0-2）**
- 2分：满足任一：(a) 至少两只同时满足"收盘价 < MA50"与"MA5 < MA50"；(b) SPY收盘价 < MA200。
- 0分：不满足2分，且三只收盘价均 ≥ 各自MA50，同时最多一只 < 各自MA20。
- 1分：其余有效组合。三环节不参与计分。

**二、广度（0-2）**
- 2分：满足任一：(a) L<40%，且 F<F5、W<W5；(b) F<40%，且 F<F5。
- 0分：L≥50%。
- 1分：其余有效组合。

**三、VIX**：与规则A相同。

**四、利率**：与规则A相同。

**五、信用（0-2）**
- O1 须为基准日之前最近一个美国债券市场营业日的观测，且在分析时点前已发布；否则记"待补：数据滞后"。
- O6 为 O1 之前第5个债券市场营业日的观测；月末周末观测不计入；该日缺失时记待补。
- 2分：ΔOAS≥20，或 O1≥4.00%（此时无需O6）。
- 0分：ΔOAS≤5，且 O1<4.00%。
- 1分：其余。

### 7.4 v3-R1 相对 v2 的四处实质修改

| 修改 | v2 | v3-R1 | 修复的问题 | 代价 |
|---|---|---|---|---|
| 1. MA50 持续性过滤 | 两只收盘价低于MA50即2分 | 两只同时满足收盘价与MA5都低于MA50 | 价格贴着MA50来回穿越时分数频繁跳动 | 真实破位后可能晚1至3天才得2分 |
| 2. 三环节移出计分 | 完成三环节即2分 | 不计分 | 路径不单调、有效期不明、与0分条件重叠 | 可能漏掉MA50之上的局部结构破坏 |
| 3. 广度第二个2分条件 | S5FI<40%且SPY接近20日高点 | S5FI<40%且较5日前下降 | 广度不变、指数下跌时，广度分数反而下降 | 放弃"指数高位、广度背离"报警，交给过热预警框架 |
| 4. OAS时效与计数 | 滞后超过1日封顶1分；按观测个数计数 | 滞后改为待补；按债券营业日计数，排除月末周末观测 | 数据陈旧被当作低风险；月末周末观测导致错位 | 信用维度待补的频率上升 |

## 9. 回测方案（预先登记，看结果前已写定）

### 9.1 四个阶段

| 阶段 | 内容 | 用途 |
|---|---|---|
| 一、数据审计 | 确认各数据的免费可得性与历史覆盖 | OAS 在 FRED 只有最近三年；2010至2024年的历史回测因此不可执行 |
| 二、与结果无关的诊断 | 在 OAS 可得窗口内逐日计算，统计各维度分数变化次数、报警天数比例、待补比例 | 回答"分数是否频繁跳动"，不需要知道后续涨跌，不受事后偏差影响 |

### 9.3 风险事件与预警定义

- **风险事件**：以基准日收盘价为起点，之后20个交易日内：
  - 标普500指数最低收盘价跌幅 ≥ 5%，或
  - QQQ最低收盘价跌幅 ≥ 7%
  - 任一成立即为风险事件。只用收盘价，不用盘中低点。
- 字段口径（2026-09-27 确定）：
  - 基准日口径跌幅 `drawdown_from_base`：以基准日收盘价为起点，结果窗口内最低收盘价的跌幅。风险事件按此判断。
  - 峰谷回撤 `peak_to_trough_drawdown`（参考字段）：结果窗口内从最高收盘价到其后最低收盘价的跌幅；峰值的计算起点包含基准日收盘价（之后没有更高收盘价时，峰值即基准日）。不用于判断事件或接近事件。
  - 接近事件（仅作参考，不改变风险事件的定义）：未构成风险事件，但按基准日口径标普500跌幅 ≥ 4% 或 QQQ ≥ 6%。
- **预警**：总分 ≥ 3。
- **严格确认**：价格=2、广度=2，且信用或VIX=2。与预警分开评价。

| | 发生风险事件 | 未发生 |

| 未预警 | 漏报 | 正确静默 |

### 9.4 评价指标与通过标准（均为预设的设计选择）

- 指标：命中率、误报率、预警准确率、正确静默率、报警比例、数据完整率、命中样本的提前量。
- 待补时：总分下限≥3视为预警；上限<3视为未预警；否则状态未知，单独报告。
- 通过标准（同时满足）：至少90%样本可确定预警状态；至少40个事件和40个非事件样本；v3-R1 相对 v2-M 误报率差的95%区间上限<0；命中率差的95%区间下限>−5个百分点。
- 样本不足时结论为"不确定"，不得修改标准来凑结论。

### 9.5 纪律

- 外部冲击引发的事件保留在样本中，不因"不可预见"而删除漏报。
- 结果标签由程序计算（`market-risk outcome compute`；字段见第9.3节），与评分代码隔离（有测试保证：评分、prompt 生成与快照代码不得读取标签），用户抽查核对；不告诉 ChatGPT。（2026-09-27 修改，原为"由用户自行核算"）
- 每个样本记录"是否贴近门槛"，以便日后判断分数的稳定性。
