## 二、用法

```bash
python gen_scenarios_v20.py <临时目录> [all|manual]
python audit_v20.py <场景.json> <输出.json>
```

- **退出码（修订二第三节，冻结接口）**：

  | 退出码 | 含义 |
  | --- | --- |
  | 0 | 正常完成，包括“缺值无法评价”“无合格候选”等非计算失败的登记出口，以及确认性检验的“计算无效”（缺价、R2 无法计算、主设定 n ÷ b < 2 等） |
  | 1 | 未能形成或写出有效报告的未捕获故障（例如输出文件所在目录不存在）。计算中的异常都已捕获，记为“未预期异常”，退出码 3 |
  | 2 | 命令行参数错误 |
  | 3 | 成功形成结构化停止报告。原因见 `stop_reason.reason`，不得把 3 单独解释为某一种原因 |

- **`stop_reason` 的取值（修订二第三、五节，补充条文第五节）**：

  | `reason` | 情形 |
  | --- | --- |
  | `输入校验失败` | 截止日以内的前缀有非法格式、缺少必需字段、日期重复或乱序、日期无法解析、价格非正或非有限、参数不合法；给定初始状态不在状态域内；轴含非 NYSE 交易日（与整行缺失同时出现时同样停止，不被缺失标记掩盖） |
  | `未预期异常` | 内部一致性断言失败，以及其他未归入上两类的情形（含登记未覆盖的 R2 判定情形）。保留 `exception_type`（异常类型）、`message`（原始信息）与 `traceback`（调用栈）；不伪装成缺值，也不仅凭发生异常就断言为算法错误 |
  | `计算失败` | 杠杆因子不为正、非有限值、对账不符（候选、主参照、执行政策模拟、一直持有任一对象）。整体停止，附 `failures` |
  | `未收敛` | 开发期内或确认性检验窗口开始前任一对象不收敛 |
  | `评价窗口为空` | 可计入收益区间数 n = 0（按 n 判断）。细分码 `sub_reason`：`起点等于最后一个收盘日` 或 `起点晚于最后一个收盘日`；另输出 `n`、`j0_index`、`E_index` |
  | `t0 不存在` | 五个通道的输入从未同时完整（修订二第六节 Q16） |
  | `提示段起始状态无法确定` | 补充第 11 条（c）与第 14 条：提示段起始日的前一信号日状态无法确定 |

  “缺少必需价格”不是停止原因：它使相应的 R2 记为“无法计算”、选择程序走“缺值无法评价”出口、确认性检验记为“计算无效”，退出码为 0。比对同一接口时，退出码、出口、原因码与细分码精确一致；调用栈与平台相关的错误文字不要求逐字相同。
- **截止日（修订二第一节）**：历史计算只验证、只使用截止日以内的前缀。日期解析、长度检查、日历检查都在截取前缀之后进行；截止日之后的记录、缺值与非法内容不改变截止日以内的计算结果、出口或退出码。截止日之后只在诊断字段 `input_checks.post_cutoff` 中记录行数，标注“不影响历史计算”，内容记为“未验证”（不记为“合法”）。
- **整行缺失（修订二第二节）**：给出 `calendar: "NYSE"` 时，在派生输入层按 NYSE 日历标记截止日以内缺失的交易日，并把该日两资产价格设为 None（缺失标记，不补价、不插值、不前值填充，也不压缩窗口）。原始场景文件不修改；原始日期轴 `input_checks.raw_axis` 与派生日期轴 `input_checks.derived_axis` 分别输出，`input_checks.added_dates` 列出新增日期、缺失资产与原因。后续比对分层进行：输入层核对缺失日期与结构化原因，算法层只在双方日期轴、缺失标记与初始条件相同时比较（修订二第八节）。
- **核对范围（修订二第四节第 9 条）**：工具同时核对信号模拟与执行政策研究模拟。规则层（前向运行）允许把止损判断推迟到净值可得日；这一规则不得误用于研究层，研究层不得在净值不可得时继续假定止损未触发。

## 三、场景格式（JSON）

公共字段：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `kind` | 字符串 | `signal`、`full`、`exec`、`r2`、`bootstrap`、`confirm` 之一 |
| `name` | 字符串 | 场景名（生成脚本写入） |
| `axis` | 字符串列表 | 交易日轴。截止日以内的部分须无重复、严格递增（按字符串比较）；交易日的加减一律按轴上的位置计算 |
| `calendar` | `"NYSE"` 或省略 | 给出时，用 NYSE 交易日历核对截止日以内的轴（补充第 18 条、修订二第二节）：轴上有非交易日为输入校验失败；缺少的交易日在派生输入层标记为两资产缺价，见第二节 |
| `cutoff` | 字符串或省略 | 截止日（含），须在轴上（取第一次出现的位置）；省略时为轴的最后一日。截止日之后的内容不验证、不参与计算 |
| `prices` | `{"SPX": [...], "QQQ": [...]}` | 与轴等长的收盘价；`null` 表示缺价。读入时按两位小数 ROUND_HALF_UP 取整（补充第 1 条），以 Decimal 计算 |
| `params` | `"registered"` 或 `[[K, "θ", h], ...]` | `"registered"` 为登记的 27 组，按先 K、再 θ_P、再 h 的登记顺序 |
| `meta` | 对象 | 出处与说明，工具不读 |

各类场景另有的字段：

| 类别 | 另有字段 | 计算内容 |
| --- | --- | --- |
| `signal` | `start`：`{"mode": "t0"}`，或 `{"mode": "given", "day": 下标, "state": {"ch": {...}, "S": ..., "c1": ..., "c2": ...}}`；`enumerate`：`{"start": 下标}`（可选）；`reference`：`{"start": 下标}`（可选） | 输入派生量、通道与状态机。给定 `enumerate` 时，从该日起做通道收敛与系统收敛的枚举。给定 `reference` 时，做主参照的三种初始状态运行 |
| `full` | `r1_segments`：`[[起日, 止日], ...]`（可选，按区间末日） | 全部：t0、收敛、j₀、信号模拟、执行政策模拟、一直持有、主参照、R2 事件与判定、提示段账、R1、选择程序 |
| `exec` | `S`、`all_valid`（与轴等长），`j0`（下标），`E`（下标，可选），以及 `U`（逐区间等权日收益，与轴等长）或 `prices` | 直接给定信号结果，只做信号模拟、执行政策模拟与一直持有 |
| `r2` | `S`（与轴等长，元素为 `正常`、`一级`、`二级` 或 `null`；`null` 表示无法确定），`f`（窗口第一个信号日下标），`E`（窗口最后一个信号日下标） | 直接给定逐日状态，计算 R2 事件、逐事件判定与提示段账 |
| `bootstrap` | `items`：`[{"seed", "b", "n", "count"}]` | 平稳自助法前 `count` 条完整索引序列 |
| `confirm` | `params`：`[K, "θ", h]`；`window_start`：首个区间的起点收盘日；`half_split`：后半第一个区间的末日；`B`、`seeds`（可选，默认登记值） | 确认性检验 |

## 四、输出字段

### 4.1 约定

- **顶层字段**：
  - `tool`：工具版本（本版 `v20-indep-3`）；
  - `kind`、`name`；
  - `exit_code`：退出码；
  - `stop_reason`：停止报告时出现，见第二节；
  - `input_checks`（`signal`、`full`、`confirm` 场景）：
    - `post_cutoff`：`note` = `不影响历史计算`，`status` = `未验证`，`axis_rows_after_cutoff`，`price_rows_after_cutoff`（各资产）；
    - `raw_axis`：截止日以内的原始日期轴；`derived_axis`：派生日期轴（补入整行缺失的交易日后）；
    - `added_dates`：`[{date, assets, reason}]`，`reason` = `预期交易日整行缺失`。

- **数值类型**：
  - Decimal 量（价格、H、D、均线之和）以十进制文字输出。
  - float64 量以 JSON 数字输出（Python `repr`，可逐位还原）；非有限值写成文字。
- **日期**：一律输出交易日标签。下标超出轴时写 `窗口外+k`。
- **区间标记**：收益区间 j 指第 j−1 日收盘至第 j 日收盘，以区间末日 j 标记（补充第 12 条）。

### 4.2 输入（每资产每日）`inputs.SPX[i]`、`inputs.QQQ[i]`

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `day` | 字符串 | 交易日 |
| `close` | 字符串或 null | 收盘价（两位小数）；null 为缺价 |
| `has_close` | 布尔 | 收盘价是否存在 |
| `h_complete` | 布尔 | 63 日最高价 H 是否完整：最近 63 个交易日（含当日）全部存在。轴起点之前的位置按不存在处理 |
| `h` | 字符串或 null | 完整时为 H，不完整时为 Ĥ（窗口内存在价格的最大值）；窗口内没有价格时为 null |
| `d` | 字符串或 null | D 或 D̂ = 1 − C ÷ H（或 Ĥ），用 28 位有效数字的 Decimal 除法得出，只作显示；比较一律用乘法形式（补充第 2 条）。当日缺价时为 null |
| `reach` | `{θ: [布尔, 布尔]}` | 对场景中出现的每个 θ_P，分别给出是否达到 θ_P 与是否达到 2θ_P：C ≤ (1 − θ)·H（或 Ĥ） |
| `nl` | `1`、`0` 或 `"未知"` | 三值 20 日新低（补充第 8 条） |
| `q` | 整数 | 距最近一次 NL = 1 或 NL 未知的交易日数；当日 NL 为 1 或未知时为 0 |

### 4.3 输入（SPX 每日）`inputs.SPX_MA[i]`

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `ma_complete` | 布尔 | 200 日均线窗口是否完整：最近 200 个交易日（含当日）全部存在 |
| `ma_sum` | 字符串或 null | 200 日收盘价之和；不完整时为 null |
| `below_ma` | 布尔或 null | 是否低于均线：200·C < 之和；不完整时为 null |

### 4.4 通道与状态机（每组参数每日）`groups[组].days[i]`

组名的写法为 `K=5,θ=0.02,h=3`。首日为初始化日（t0 或给定起点）：`init = true`，只有 `ch`、`S`、`c1`、`c2`。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `day`、`idx` | 字符串、整数 | 交易日与其在轴上的下标 |
| `init` | 布尔 | 是否为只初始化、不更新的起点 |
| `ch` | `{通道: 状态}` | P_SPX、P_QQQ、PR_SPX、PR_QQQ 的状态 ∈ {激活, 已武装未激活, 未武装未激活}；MR 的状态 ∈ {激活, 已武装未激活} |
| `valid` | `{通道: 布尔}` | 五个通道各自是否有效 |
| `all_valid` | 布尔 | 五个通道是否全部有效 |
| `items` | 6 个布尔 | A₁ 的六项。前四项即 A₂ 的四项：(1) 两资产收盘价都存在；(2) H 都完整；(3) PR_SPX、PR_QQQ 都未激活；(4) Q_SPX ≥ K 且 Q_QQQ ≥ K。另两项：(5) MA 完整且 MR 未激活；(6) P_SPX、P_QQQ 都未激活 |
| `A2`、`A1` | 布尔 | A₂(d)、A₁(d) |
| `c1`、`c2` | 整数 | 截断在 h 的连续计数 |
| `L` | 整数 | 证据级别 L_d ∈ {0, 1, 2} |
| `S` | 字符串 | 风险状态 S_d |
| `transition` | null 或对象 | 当日系统转换：`{"type": "升级"/"降级", "from", "to"}` |
| `direct_to_2` | 布尔 | 是否由正常直接进入二级：S_{d−1} = 正常 且 L_d = 2 |

### 4.5 收敛

每组参数的输出中：

| 字段 | 类型 | 含义 |

| `channel_conv[通道].runs` | `{初始状态: [逐日状态]}` | 每种初始状态的逐日通道状态，自起点至收敛日（含） |
| `channel_conv[通道].conv_day` | 字符串或 null | 该通道收敛日：全部运行首次相同之日；不收敛为 null |
| `kappa_ch` | 字符串 | κ_通道：五个通道收敛日的最大者 |
| `system_conv.start` | 字符串 | κ_通道 |
| `system_conv.inits` | 列表 | 3 × (h+1)² 种 (S, c₁, c₂) 初始组合，顺序为 S（正常、一级、二级）、c₁、c₂ 递增 |

| 字段 | 含义 |

| `window_first_signal_day` | j₀ − 1 |
| `E` | 窗口最后一个信号日 |

### 4.6 主参照（每日）`reference.days[i]`

| 字段 | 类型 | 含义 |

### 4.7 执行

信号模拟与执行政策模拟分开输出：`groups[组].signal_sim`、`groups[组].exec_sim`、`reference.signal_sim`、`reference.exec_sim`，以及 `hold`（一直持有）。

**信号模拟 `signal_sim`：**

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `plan[i]` | 对象 | 计划目标，见下 |
| `plan[i].exec_idx` | 字符串 | 执行日 |
| `plan[i].signal_idx` | 字符串 | 信号日 |
| `plan[i].S` | 字符串 | 信号日的 S |
| `plan[i].exposure` | 字符串 | 目标仓位（总暴露）：1.4、0.6、0.3 |
| `plan[i].core_w`、`plan[i].lev_w` | 字符串 | 核心权重 0.6·e_核心，杠杆权重 0.4·e_杠杆 |
| `plan[i].source` | 字符串 | 来源：`初始建仓` 或 `系统` |
