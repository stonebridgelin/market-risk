# 波段预警 v2.0 独立复核工具

本目录按《v20 阶段三实施指令》第五节编写，供原会话的比对测试（`tests/test_v20_independent_compare.py`）与人工复核使用。

| 文件 | 用途 |
| --- | --- |
| `audit_v20.py` | 复核工具：读一个场景文件，逐日输出第五节第 2 部分的字段 |
| `gen_scenarios_v20.py` | 场景生成脚本：按固定种子把场景写入给定的（临时）目录 |
| `README.md` | 本说明：用法、场景格式、输出字段、场景清单与种子、对规格的疑问、局限 |

## 一、独立性与技术约束

- **编写依据**：只读了以下资料。
  - 登记 `docs/research/波段预警研究规格_v2.0_登记.md`；
  - 产品规格 `docs/product/产品规格_修订一_第40版.md`；
  - `docs/research/v20_实施口径补充.md` 第 1 至 20 条；
  - `docs/research/v20_阶段二执行说明.md`；
  - `docs/research/v20_阶段三实施指令.md` 第五节。
- **未打开的内容**：编写时没有打开、搜索或引用以下内容。
  - 项目包源码；
  - 名称含 v20 或 wavewarn 的测试文件；
  - 本目录以外的既有独立复核工具。
- **技术约束**：
  - 两个脚本都不导入项目包；
  - 不含行情目录的字面路径，没有网络调用；
  - 只用 numpy、pandas_market_calendars 与标准库。pandas_market_calendars 只用于生成和核对 NYSE 交易日轴。
- **局限（如实说明）**：
  - 会话隔离只是流程安排，没有技术手段保证编写会话未看到项目实现。
  - 两个会话可能对规格作出相同的误读，这种共同误读比对发现不了，仍须靠人工例子与复核者核对。
  - 下文第六节列出的“待确认”口径，是本工具不得不作的读法；若与项目实现一致，也不表示该读法已被确认。

## 二、用法

```bash
python gen_scenarios_v20.py <临时目录> [all|manual]
python audit_v20.py <场景.json> <输出.json>
```

- 退出码：0 表示正常，2 表示参数错误，3 表示“停下报告”。`full` 场景中途停下（不收敛、t0 不存在、窗口为空）时，输出含 `stop` 字段与已算出的部分，退出码也为 3。
- “停下报告”指登记未覆盖或登记要求停下的情形，例如 MR 出现第三种状态、R2 的提示段起始日前一日状态无法确定。此时输出文件为 `{"停下报告": 原因}`。
- 场景中截止日（`cutoff`）之后的数据在读入时即截断，不参与任何计算。

## 三、场景格式（JSON）

公共字段：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `kind` | 字符串 | `signal`、`full`、`exec`、`r2`、`bootstrap`、`confirm` 之一 |
| `name` | 字符串 | 场景名（生成脚本写入） |
| `axis` | 字符串列表 | 交易日轴。日期标签无重复，按时间顺序排列；交易日的加减一律按轴上的位置计算 |
| `calendar` | `"NYSE"` 或省略 | 给出时，用 NYSE 交易日历核对轴，以检测整行缺失（补充第 18 条） |
| `cutoff` | 字符串或省略 | 截止日（含），须在轴上；省略时为轴的最后一日 |
| `prices` | `{"SPX": [...], "QQQ": [...]}` | 与轴等长的收盘价；`null` 表示缺价。读入时按两位小数 ROUND_HALF_UP 取整（补充第 1 条），以 Decimal 计算 |
| `params` | `"registered"` 或 `[[K, "θ", h], ...]` | `"registered"` 为登记的 27 组，按先 K、再 θ_P、再 h 的登记顺序 |
| `meta` | 对象 | 出处与说明，工具不读 |

各类场景另有的字段：

| 类别 | 另有字段 | 计算内容 |
| --- | --- | --- |
| `signal` | `start`：`{"mode": "t0"}`，或 `{"mode": "given", "day": 下标, "state": {"ch": {...}, "S": ..., "c1": ..., "c2": ...}}`；`enumerate`：`{"start": 下标}`（可选）；`reference`：`{"start": 下标}`（可选） | 输入派生量、通道与状态机。给定 `enumerate` 时，从该日起做通道收敛与系统收敛的枚举。给定 `reference` 时，做主参照的三种初始状态运行 |
| `full` | `r1_segments`：`[[起日, 止日], ...]`（可选，按区间末日） | 全部：t0、收敛、j₀、信号模拟、执行政策模拟、一直持有、主参照、R2 事件与判定、提示段账、R1、选择程序 |
| `exec` | `S`、`all_valid`（与轴等长），`j0`（下标），`E`（下标，可选），以及 `U`（逐区间等权日收益，与轴等长）或 `prices` | 直接给定信号结果，只做信号模拟、执行政策模拟与一直持有 |
| `r2` | `S`（与轴等长，元素为 `正常`、`一级`、`二级` 或 `null`；`null` 表示无法确定），`f`（窗口第一个信号日下标），`E`（窗口最后一个信号日下标） | 直接给定逐日状态，计算 R2 事件、逐事件判定与提示段账 |
| `bootstrap` | `items`：`[{"seed", "b", "n", "count"}]` | 平稳自助法前 `count` 条完整索引序列 |
| `confirm` | `params`：`[K, "θ", h]`；`window_start`：首个区间的起点收盘日；`half_split`：后半第一个区间的末日；`B`、`seeds`（可选，默认登记值） | 确认性检验 |

## 四、输出字段

### 4.1 约定

- **数值类型**：
  - Decimal 量（价格、H、D、均线之和）以十进制文字输出。
  - float64 量以 JSON 数字输出（Python `repr`，可逐位还原）；非有限值写成文字。
- **日期**：一律输出交易日标签。下标超出轴时写 `窗口外+k`。
- **区间标记**：收益区间 j 指第 j−1 日收盘至第 j 日收盘，以区间末日 j 标记（补充第 12 条）。

### 4.2 输入（每资产每日）`inputs.SPX[i]`、`inputs.QQQ[i]`

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `day` | 字符串 | 交易日 |
| `close` | 字符串或 null | 收盘价（两位小数）；null 为缺价 |
| `has_close` | 布尔 | 收盘价是否存在 |
| `h_complete` | 布尔 | 63 日最高价 H 是否完整：最近 63 个交易日（含当日）全部存在。轴起点之前的位置按不存在处理 |
| `h` | 字符串或 null | 完整时为 H，不完整时为 Ĥ（窗口内存在价格的最大值）；窗口内没有价格时为 null |
| `d` | 字符串或 null | D 或 D̂ = 1 − C ÷ H（或 Ĥ），用 28 位有效数字的 Decimal 除法得出，只作显示；比较一律用乘法形式（补充第 2 条）。当日缺价时为 null |
| `reach` | `{θ: [布尔, 布尔]}` | 对场景中出现的每个 θ_P，分别给出是否达到 θ_P 与是否达到 2θ_P：C ≤ (1 − θ)·H（或 Ĥ） |
| `nl` | `1`、`0` 或 `"未知"` | 三值 20 日新低（补充第 8 条） |
| `q` | 整数 | 距最近一次 NL = 1 或 NL 未知的交易日数；当日 NL 为 1 或未知时为 0 |

### 4.3 输入（SPX 每日）`inputs.SPX_MA[i]`

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `ma_complete` | 布尔 | 200 日均线窗口是否完整：最近 200 个交易日（含当日）全部存在 |
| `ma_sum` | 字符串或 null | 200 日收盘价之和；不完整时为 null |
| `below_ma` | 布尔或 null | 是否低于均线：200·C < 之和；不完整时为 null |

### 4.4 通道与状态机（每组参数每日）`groups[组].days[i]`

组名的写法为 `K=5,θ=0.02,h=3`。首日为初始化日（t0 或给定起点）：`init = true`，只有 `ch`、`S`、`c1`、`c2`。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `day`、`idx` | 字符串、整数 | 交易日与其在轴上的下标 |
| `init` | 布尔 | 是否为只初始化、不更新的起点 |
| `ch` | `{通道: 状态}` | P_SPX、P_QQQ、PR_SPX、PR_QQQ 的状态 ∈ {激活, 已武装未激活, 未武装未激活}；MR 的状态 ∈ {激活, 已武装未激活} |
| `valid` | `{通道: 布尔}` | 五个通道各自是否有效 |
| `all_valid` | 布尔 | 五个通道是否全部有效 |
| `items` | 6 个布尔 | A₁ 的六项。前四项即 A₂ 的四项：(1) 两资产收盘价都存在；(2) H 都完整；(3) PR_SPX、PR_QQQ 都未激活；(4) Q_SPX ≥ K 且 Q_QQQ ≥ K。另两项：(5) MA 完整且 MR 未激活；(6) P_SPX、P_QQQ 都未激活 |
| `A2`、`A1` | 布尔 | A₂(d)、A₁(d) |
| `c1`、`c2` | 整数 | 截断在 h 的连续计数 |
| `L` | 整数 | 证据级别 L_d ∈ {0, 1, 2} |
| `S` | 字符串 | 风险状态 S_d |
| `transition` | null 或对象 | 当日系统转换：`{"type": "升级"/"降级", "from", "to"}` |
| `direct_to_2` | 布尔 | 是否由正常直接进入二级：S_{d−1} = 正常 且 L_d = 2 |

| 字段 | 类型 | 含义 |

| `channel_conv[通道].runs` | `{初始状态: [逐日状态]}` | 每种初始状态的逐日通道状态，自起点至收敛日（含） |
| `channel_conv[通道].conv_day` | 字符串或 null | 该通道收敛日：全部运行首次相同之日；不收敛为 null |

| `system_conv.start` | 字符串 | κ_通道 |
| `system_conv.inits` | 列表 | 3 × (h+1)² 种 (S, c₁, c₂) 初始组合，顺序为 S（正常、一级、二级）、c₁、c₂ 递增 |
| `system_conv.runs` | 列表 | 与 `inits` 对应的逐日 [S, c₁, c₂]，自 κ_通道 至系统收敛日（含）。κ_通道 之后各运行的通道状态相同（见 `days[i].ch`），所以完整状态 = 当日 `ch` + 该运行的 [S, c₁, c₂] |

| 字段 | 含义 |

| `t0` | t0 |
| `reference_conv` | 主参照三种初始状态的逐日 L_参照、S_参照，以及收敛日 |

### 4.7 执行

信号模拟与执行政策模拟分开输出：`groups[组].signal_sim`、`groups[组].exec_sim`、`reference.signal_sim`、`reference.exec_sim`，以及 `hold`（一直持有）。

**信号模拟 `signal_sim`：**

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `plan[i]` | 对象 | 计划目标，见下 |
| `plan[i].exec_idx` | 字符串 | 执行日 |
| `plan[i].signal_idx` | 字符串 | 信号日 |
| `plan[i].S` | 字符串 | 信号日的 S |
| `plan[i].exposure` | 字符串 | 目标仓位（总暴露）：1.4、0.6、0.3 |
| `plan[i].core_w`、`plan[i].lev_w` | 字符串 | 核心权重 0.6·e_核心，杠杆权重 0.4·e_杠杆 |
| `plan[i].source` | 字符串 | 来源：`初始建仓` 或 `系统` |
| `plan[i].cap_in_force`、`plan[i].cap_binding` | 布尔 | 上限是否生效（信号模拟中恒为假） |
| `switches` | 整数 | 目标状态切换次数（自 j₀+1 起） |
| `switch_list[k]` | 对象 | 每次切换：`exec_idx`、`from`、`to`、`delta`（带符号的暴露变化）、`abs_delta`、`stages`（阶段变化数，正常 0、一级 1、二级 2；涉及现金时为 null） |
| `nav[i]` | 对象 | 净值，见第 4.8 节 |
| `failed` | null 或对象 | 失败类别：`缺价`（附 `missing`）、`杠杆因子不为正`、`非有限值`、`对账不符` |
| `summary` | null 或对象 | `W_end`、`lnW_end`（= ln W_末）、`sum_log`（Σ ln(1 + R_j)）、`recon_ok`（两者之差 ≤ 1e-10）、`mdd`（最大回撤） |

**执行政策模拟 `exec_sim`：**

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `days[i]` | 对象 | 逐日记录，各字段见下 |
| `days[i].U`、`R`、`lev_factor`、`lev_ok`、`W` | 数值、布尔 | 净值，同第 4.8 节 |
| `days[i].held_exposure` | 字符串 | 当日收盘执行后的模拟暴露 |
| `days[i].mode` | 字符串 | `持仓`、`离场待执行`、`现金`、`重入待执行` |
| `days[i].S`、`all_valid` | 字符串、布尔 | 信号记录（五通道是否全部有效） |
| `days[i].base` | 数值或 null | 本轮基准（持仓时） |
| `days[i].cooldown` | 布尔 | 是否在冷却期 s+1 至 s+10（现金时） |
| `days[i].cap` | 字符串 | 当日结束时上限 U ∈ {一级, 无} |
| `days[i].next_target` | 对象 | 次日计划目标：`exec_idx`、`exposure`、`core_w`、`lev_w`、`source`（初始建仓、系统、止损、现金、重入）、`cap_in_force`（U = 一级 是否在效）、`cap_binding`（上限是否实际压低了目标） |
| `events` | 列表 | 止损确认、止损执行、重入信号、上限设置、重入执行、上限解除，各附日期 |
| `switches`、`switch_list` | | 同信号模拟 |
| `summary` | 对象 | 同信号模拟，另有 `stops`（止损次数）与 `reentries`（重入次数） |

`groups[组]` 另有 `r1`、`r2`、`ledger`，见第 4.9 至 4.11 节。

### 4.8 净值（每日）`nav[i]`

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `U` | float | 两资产等权日收益 U_j = 0.5·(C_SPX,j ÷ C_SPX,j−1 − 1) + 0.5·(C_QQQ,j ÷ C_QQQ,j−1 − 1)。Decimal 价格先转 float64 再相除 |
| `R` | float | 组合日收益 R_j = 0.6·e_核心·U_j + 0.4·e_杠杆·2·U_j（按此顺序计算） |
| `lev_factor` | float 或 null | 杠杆暴露为正时的 1 + λU_j；否则为 null |
| `lev_ok` | 布尔或 null | 1 + λU_j > 0 的检查结果 |
| `W` | float | 净值；j₀ 收盘记为 1 |

- ln W 见 `summary.lnW_end`。
- 遇缺价时：`failed = {"type": "缺价", "missing": [[资产, 日期], ...]}`，`nav` 与 `summary` 为 null。
- 缺价清单列出 [j₀, E] 内两资产的全部缺价日。

### 4.9 R1 `r1`

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `computable` | 布尔 | 是否可计算 |
| `mdd_signal` | float | 信号模拟的最大回撤 |
| `mdd_hold` | float | 一直持有的最大回撤 |
| `ok` | 布尔 | 是否满足 mdd_signal ≤ mdd_hold ÷ 2 |
| `ratio` | float 或 `"无定义"` | 回撤比；一直持有回撤为 0 时为 `"无定义"` |
| `segments[k]` | 对象 | 场景给定分段的回撤比：`from_idx`、`to_idx`、`mdd_signal`、`mdd_hold`、`ratio`（或 `"无定义"`） |

### 4.10 R2 事件与判定

**事件**（`r2_events[资产][k]`；`r2` 场景为 `events[资产][k]`）：

| 字段 | 含义 |
| --- | --- |
| `P` | 事件高点日 |
| `C_P` | 高点收盘价 |
| `T3` | P 之后第一个收盘价 ≤ 0.97·C_P 的日 |
| `T5` | 确认日 |
| `Tr` | 低点日 |
| `C_Tr` | 低点收盘价 |
| `End` | 结束日 |
| `unfinished` | 是否未结束 |

`r2_events_error[资产]`：最早收盘价之后有缺价时，标签无法生成的原因（补充第 18 条）。

**判定**（`groups[组].r2[资产]`；`r2` 场景为 `judge[资产]`）：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `events[k].category` | 字符串 | 左截断、输入不足、持续覆盖达标、新提示达标、提示中断、迟到、漏报 |
| `events[k].first_new` | 字符串或 null | 首次新提示日（只对新提示达标） |
| `events[k].first_new_confirmable` | 布尔 | 为真时 `first_new` 是“首次可确认的新提示日”（补充第 20 条） |
| `events[k].exec_idx` | 字符串或 null | 可执行日 = 首次新提示日的下一交易日 |
| `events[k].offset_vs_T3` | 整数或 null | 可执行日相对 T3 的交易日偏移 |
| `events[k].peak_new_uncertain` | 布尔 | P 当日是否为真实的新提示无法确定 |
| `counts` | 对象 | 各类件数 |
| `denominator` | 整数 | 分母 = 全部非左截断事件 |
| `passed` | 整数 | 达标数 |
| `new_only` | 整数 | 只计新提示的件数 |
| `computable` | 布尔 | 分母是否大于 0 |
| `ratio_ok` | 布尔或 null | 是否达到 60%：达标 × 10 ≥ 分母 × 6 |
| `excluding_insufficient` | `[达标, 分母]` 或 `"无定义"` | 剔除输入不足后的结果 |

### 4.11 提示段账 `ledger`

| 字段 | 类型 | 含义 |

## 六、对规格的疑问（待确认，按指令只报告、不自行选择）

以下各项本工具都作了一种读法，以便工具能运行。每项列出原文出处、本工具的读法与理由。请负责人确认或改定；改定后工具须相应修改。

- **Q1（登记例子与定义不一致）**：
  - 原文：登记第八节第 2 小节 MR 构造例子写 t0+1 日“MA 不完整”、t0+2 日“MA 完整”。
  - 问题：按第四节第 1 小节，t0 当日五个通道（含 MR）的输入已完整。t0+1 日要变为不完整，只能是 t0+1 日或其后的 SPX 缺价，而缺价会留在 200 日窗口内约 200 日，所以 t0+2 日不可能恢复完整。规则本身（两种状态、退出与进入条件）清楚。
  - 本工具：把三日平移到“一次缺价离开 200 日窗口”的前后核对。
- **Q2（主参照的收敛枚举起点）**：
  - 原文：登记第四节第 2 小节只写“S_参照 以三种初始值各运行一次，取首次相同之日”，没有写起点日，也没有写实际运行的初始值。
  - 本工具：按“风险状态机自 t0 起连续运行”（第四节首段），从 t0 起运行三种初始值，t0 当日只初始化。逐日 S_参照 自收敛日起输出；收敛前三种运行全部输出。
  - 影响：起点决定主参照收敛日，进而可能影响 κ_全 与 j₀。
- **Q3（执行政策模拟遇缺价）**：
  - 原文：登记第八节第 4 小节写“停止受影响窗口的精确净值评价”；第八节第 5 小节又写组合止损“在价格可得的第一个交易日判断”（后者看来指前瞻运行）。
  - 本工具：[j₀, E] 内任一资产任一日缺价，信号模拟、执行政策模拟、一直持有与主参照的净值都记为“无法计算”，缺失日期清单列出窗口内全部缺价日。执行政策模拟不再给出逐日计划，因为止损判断依赖净值。
  - 未定之处：止损后处于现金期间的缺价是否算“所需价格”；缺价之后是否还应给出计划目标。
- **Q4（出口的优先顺序）**：
  - 原文：登记第五节第 2 小节列了“缺值无法评价”与“计算失败”两个出口，没有写两者同时出现时报哪一个。
  - 本工具：先判窗口内是否缺价，缺价时不再计算净值，所以不会再发现杠杆因子问题。选择程序的出口顺序为：计算失败 > 缺值无法评价 > 无合格候选 > 选定。执行政策模拟与主参照的计算失败也计为“计算失败”。
- **Q5（R2 标签遇缺价）**：
  - 补充第 18 条要求 R2 标签函数遇空价格报错。本工具在资产最早收盘价之后有缺价时不生成该资产的 R2 事件，选择程序记为“缺值无法评价”。
  - 未定之处：登记第五节第 2 小节写的“R2 无法计算”只列了“非左截断事件为 0 个”，缺价时是否也走这一出口。
- **Q6（切换的阶段数）**：
  - 原文：登记第一节第 7 小节的例子“正常→二级为 1.1 倍、二级→一级为 0.3 倍”都写成正数。
  - 本工具：同时输出带符号的变化与绝对值。执行政策模拟中涉及现金（暴露 0）的切换，阶段数记 null，因为登记的阶段只有正常、一级、二级。
- **Q7（R1 分段回撤比）**：
  - 原文：登记第五节第 1 小节要求按 1999—2009、2010—2016 及两次熊市区间报告回撤比；熊市区间的日期“同 T2”，不在本工具可读的资料中。
  - 本工具：由场景给定分段。分段内的最大回撤以分段首个区间起点收盘的净值为起点、峰值在分段内重新计算。
- **Q8（逐事件偏移字段）**：
  - “首次新提示日、可执行日、相对 T3 的偏移”只对“新提示达标”给出，其余类别为 null。
  - 原文没有写持续覆盖、迟到等类别是否也要报这些字段。
- **Q9（抽样的随机数调用形式）**：
  - 阶段二执行说明第 4 部分给出了抽样顺序：先抽首位置；之后每个位置先抽 u，u < 1/b 时重抽位置，否则环形续行。登记写“抽样顺序同 v1.2.1”，而 v1.2.1 规格不在本工具可读的资料中。
  - 本工具：B 条序列共用一个 `Generator(PCG64(seed))`，依次逐条抽取。逐次使用标量调用 `rng.integers(0, n)` 与 `rng.random()`，比较 `u < 1.0 / b`。
  - 若旧实现用批量调用或别的区间写法，索引会不同。
  - “两个长度”未写明，本工具取 250 与 1500。
- **Q10（确认性检验的窗口起点）**：
  - 原文：补充第 10 条只定义了 [j₀ − 1, E]。验证期“第一个区间”是 2016-12-30 收盘至 2017-01-03 收盘，还是其他，本工具可读的资料没有写明。
  - 本工具：由场景给出窗口起点收盘日 `window_start`，窗口第一个信号日为其前一日。
- **Q11（随机路径的“跨越 63 日与 200 日窗口的缺口”）**：
  - 本工具读作长度超过 63 日、超过 200 日的连续缺价。
- **Q12（浮点运算顺序，不是规则问题，但影响逐位相等）**：
  - 登记没有规定 U_j、R_j 的运算顺序与求和方式。
  - 本工具：U_j 与 R_j 按第 4.8 节的写法计算；ln(1 + R) 用 `math.log(1.0 + R)`；求和一律从左到右（重抽样的 Δ* 用 `numpy.cumsum` 的末项）。
  - 与项目实现若只在末位不同，属这一原因；比对时按指令第五节第 6 部分说明容差理由。
- **Q13（提示段账的事件集合）**：

  - 规格第八节第 5 条没有排除左截断事件，但也没有明说。
