# 数据留痕设计说明（T3 第一步，2026-10-01）

## 1. 范围与边界

本批只建设**存储结构与录入留痕**：记下每个手工数据读数是谁、什么时候、从哪里、以什么方式取得的，以及之后的确认与修订。

**本批不接入研究计算。** 具体地：

- 新的存储入口不替换任何评分、信号、回测或研究计算的既有输入。`breadth add`、`data build`、TradingView 导入、`data/market/` 数据集与波段预警的输入读取都没有改动，它们也不读取留痕记录。
- 不改变任何历史信号，不接入评价流程。
- 不批量导入历史数据：本批只提供录入、查询、修订与确认的能力和测试。
- 有测试检查 `scoring/`、`wavewarn/`、`research/`、`data/` 下的模块都不导入数据留痕的模块。

第一批覆盖三项手工数据：S5FI、S5TW、NDTW（`config/provenance.yaml`）。

## 2. 存放位置：以文件为准，数据库可重建

按 `docs/STORAGE.md` 的原则（数据库可以随时由文件重建），以 `data/manual/provenance/` 下的文件为准，提交 git：

| 路径 | 内容 | 写入方式 |
| --- | --- | --- |
| `data/manual/provenance/records.csv` | 留痕记录，每条一行 | 只追加；已有的行不读入改写 |
| `data/manual/provenance/confirmations.csv` | 确认记录，每条一行 | 只追加 |
| `data/manual/provenance/snapshots/<指标>/<交易日>/<SHA-256 前 12 位>_<原文件名>` | 原始快照文件 | 只新增，不覆盖 |
| `data/manual/provenance/signal_inputs.csv` | 预留：信号实际使用的输入记录编号 | 本批不写入 |

数据库的三张表由 `rebuild-db` 从上述文件重建（迁移 `0008`，`storage/schema.py` 同步）：

| 表 | 来源 |
| --- | --- |
| `provenance_records` | `records.csv` |
| `provenance_confirmations` | `confirmations.csv` |
| `signal_input_links` | `signal_inputs.csv`（本批为空） |

路径全部由 `storage/paths.py` 生成；数据库读写集中在 `storage/`。本批没有创建上述数据文件——第一次录入时才会生成。

## 3. 每条记录的字段

| 字段 | 含义 | 约束 |
| --- | --- | --- |
| `record_id` | 唯一记录编号 | `PR-` 加六位顺序号，接在已有编号的最大值之后；主键 |
| `indicator` | 指标代码 | 须在配置登记的指标内（S5FI、S5TW、NDTW） |
| `trade_date` | 指标对应的交易日 | 必填 |
| `raw_value` | 原始值 | 按录入文本原样保存（“54.670”保留末尾的 0）；须是不带符号与单位的十进制数 |
| `raw_unit` | 原始单位 | 取自配置，三项指标都是 `%` |
| `raw_basis` | 口径 | 取自配置（如“标普500成分股站上50日均线比例，日线收盘值”） |
| `raw_precision` | 精度 | 原始值的小数位数；超过 8 位拒绝录入（规范化值存为 `Numeric(20, 8)`，不做舍入） |
| `normalized_value` | 规范化值 | 0—100 的百分数，`Numeric`；不做额外舍入；超出 0 至 100 拒绝录入。与原始值并存 |
| `source` | 来源 | 必填 |
| `acquisition_method` | 取得方式 | `接口` 或 `手工录入` |
| `first_obtained_at_et` | 首次取得时间（美东） | 带时区；无法证明时留空，并且必须标“历史补录”。不早于交易日，不晚于录入时间 |
| `entered_at_utc` | 录入时间 | 程序记录 |
| `entered_by` | 录入人 | 必填 |
| `is_late` | 是否迟到 | 首次取得时间**严格晚于**指标对应交易日的美东 18:30:00 才算迟到，恰为 18:30:00 不算；首次取得时间为空时无法判断，留空 |
| `source_published_at` | 来源发布时间 | 可核实时填写；无法核实时留空，不用取得时间、录入时间或交易日代替 |
| `snapshot_path`、`snapshot_sha256` | 原始快照文件路径与 SHA-256 | 提供快照文件时由程序复制入库并计算；`provenance verify-snapshots` 逐条重算核对 |
| `data_version` | 数据版本 | 录入时 `data/market/manifest.json` 的 SHA-256；没有清单时留空 |
| `code_version`、`code_dirty` | 代码版本 | 录入时的 git 提交号；工作区有未提交改动时标“未提交改动” |
| `revises_record_id` | 修订关系 | 修订记录指向被修订的记录编号；原记录不覆盖 |
| `revision_kind` | 修订类型 | `来源修订` 或 `人工修正` |
| `correction_original_value`、`correction_corrected_value`、`correction_evidence` | 人工修正的原值、修正值与证据 | 人工修正时必填证据；原值取被修正记录的原始值，修正值即本记录的原始值 |
| `historical_backfill` | 历史补录 | 首次取得时间为空时必须为“是” |

**确认记录**（`confirmations.csv`）：`record_id`、`confirmed_by`（确认人）、`confirmed_at_utc`（确认时间）、`self_confirmed`（确认人与录入人相同）。人工修正的确认记录就是那条修正记录的确认。

**预留的关联结构**（`signal_input_links`）：`signal_key`（信号的标识）、`record_id`（外键指向留痕记录）、`note`。将来每次信号实际使用了哪些输入记录，登记在这里；本批只建字段与关联结构，不接入信号计算。

## 4. 规则

1. **只追加、不覆盖。** 录入、修订、确认都只在文件末尾追加一行。修订是一条新记录，指向被修订的记录；查询时原记录显示“被某条记录修订”。
2. **录入与确认分两步。** 刚录入的记录是“未确认”。每条记录只确认一次。不强制确认人不同于录入人（单人操作的项目，强制会使记录无法确认）；两者相同时自动标“自确认”，查询结果里显示。
3. **历史补录。** 不得把旧交易日写成当时已经取得：首次取得时间无法证明时留空并标“历史补录”，程序不会用交易日或录入时间去填。不标“历史补录”又不给首次取得时间的录入被拒绝。
4. **迟到判断。** 相对指标对应交易日的美东 18:30:00，严格晚于才算；时间以别的时区给出时先换成美东（含夏令时）。
5. **被拒绝的录入不留下任何行。**

## 5. 入口

| services 函数 | 命令 | 作用 |
| --- | --- | --- |
| `provenance_add` | `market-risk provenance add --indicator S5FI --date 2026-09-25 --value 54.67 --source "TradingView INDEX:S5FI" --method 手工录入 --by stone --first-obtained 2026-09-25T17:00-04:00` | 录入；无法证明取得时间时改用 `--backfill`；`--snapshot <文件>` 附原始快照；`--source-published <时间>` 只在可核实时填写 |
| `provenance_revise` | `market-risk provenance revise --record PR-000001 --kind 人工修正 --value 54.76 --evidence "…" …` | 修订（来源修订或人工修正） |
| `provenance_confirm` | `market-risk provenance confirm --record PR-000001 --by stone` | 确认 |
| `provenance_list` | `market-risk provenance list [--indicator S5FI] [--from 日期] [--to 日期]` | 查询 |
| `provenance_verify_snapshots` | `market-risk provenance verify-snapshots` | 原始快照哈希核对 |

每次录入、修订、确认之后按项目既有方式重建数据库（与 `review`、`material` 的做法相同）。

代码：规则在 `src/market_risk/provenance.py`（纯计算，不读写文件）；配置读取在 `provenance_config.py`；文件与数据库行在 `storage/provenance_store.py`；`storage/db.py` 的重建流程多调用一步。

## 6. 实现时做的口径选择（待负责人确认）

规格与裁决没有写明、实现时取了最保守读法的地方：

1. **原始快照可以为空。** 规格把“原始快照文件路径与 SHA-256”列为字段，没有说是否必填。实现为可选：手工看屏录入时可能没有文件。提供了就必须路径与哈希齐全。
2. **记录编号的格式**为 `PR-` 加六位顺序号。
3. **录入时间与确认时间按 UTC 保存**（项目里其他时间字段的惯例）；首次取得时间按美东保存（规格写明）。
4. **数据版本**取录入时 `data/market/manifest.json` 的 SHA-256（与回测运行记录数据集版本的做法相同）。裁决写的是“对应数据集清单的版本标识，没有就留空”；NDTW 不在该数据集里，目前也记同一个清单的哈希。
5. **首次取得时间的两条合理性检查**（不早于交易日、不晚于录入时间）是实现时加的，规格没有要求。
6. **修订记录的指标与交易日**沿用被修订的记录，不允许改。
7. **人工修正与来源修订**用 `revision_kind` 区分；只有人工修正填写原值、修正值与证据三个字段。

## 7. 本批没有做的

- 没有批量导入历史数据，没有创建 `data/manual/provenance/` 下的任何数据文件。
- 没有让任何评分、信号或研究计算读取留痕记录。
- 没有接入信号计算的输入登记（只建了关联表）。
- 没有改动真实数据库文件；它会在下一次 `rebuild-db` 或下一次录入时按迁移 `0008` 重建。
