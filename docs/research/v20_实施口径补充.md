# 波段预警 v2.0 实施口径补充（2026-10-02，负责人批准）

本文件补充登记未写明的计算口径，在看到任何 v2.0 结果之前确定；不改变登记的任何规则。

1. 价格读入：SPX、QQQ 收盘价按两位小数四舍五入（ROUND_HALF_UP）读入，与 v1.x 的 published_price 相同。
2. 数值类型：价格、均线、回撤门槛与事件门槛的比较用 Decimal，并以乘法形式比较，不做除法：D ≥ θ 写作 C ≤ (1 − θ)·H；C < MA 写作 200·C < 200 日收盘价之和；R2 事件用 C ≤ 0.95·H、C ≥ 1.05·L。对数收益、净值、Δ 与重抽样用 float64。
3. 分位数：确认性检验区间的 2.5% 与 97.5% 分位数用线性插值（NumPy 默认方法）。
4. 数据集哈希：登记第零节的 SHA-256 指把 CRLF 换为 LF 后的 UTF-8 文本的哈希（与 manifest 口径相同）。仓库文件按原始字节的 SHA-256：SPX 6941ab293eddb8201e851d873476d64c6cbd584ec9573f5ff757447173bf0b00，QQQ d14e58edcab7ec94b4e6728ce65bbbf8a0a84565d53ce951a37a4e6143a56880。阶段三两项都核对。（本条为产品经理核对时新增，不在清单第六节的 13 条疑问之内。）
5. 数据来源标识：截止日以内的行，来源列只允许 yahoo 与 correct:yahoo；其他标识报错。
6. 抽样实现：v2.0 另写平稳自助法抽样，与 v1.2.1 规格逐条一致；测试证明对登记的 5 个种子与 wavewarn.paired_test.stationary_bootstrap_indices 逐位相同（旧函数只在测试中导入），各种子的前若干条索引作为期望值存入仓库。
7. 复用：允许复用 market_risk.calendar 的 NYSE 交易日函数、storage.paths（可只新增函数）、config._read_yaml 与 ConfigError、precision.published_price 与 decimal_value、storage.provenance_store.file_sha256。其余按登记新写。
8. NL 三值的计数：NL = 1 要求今日与前 19 日的收盘价全部存在，且今日严格低于前 19 日的最小值；NL = 0 要求今日存在、前 19 日里存在的价格至少 15 个，且今日不低于这些价格的最小值；其余为未知。与 v1.x 已确认的实现（features.new_low20）一致。

以下第 9 至 13 条为 2026-10-02 负责人批准（阶段二实施指令修订稿四第二节）。

9. 主参照的“输入全部有效”：信号日 SPX 收盘价存在，且 SPX 200 日均线窗口完整。用于主参照执行政策模拟的重入条件与 U 解除条件。
10. 评价窗口的信号日为 [j₀ − 1, E]，E 为截止日以内的最后一个交易日。“窗口第一个信号日”= j₀ − 1，“窗口最后一个信号日”= E。
11. 设 f 为窗口第一个信号日。若 S_f 为提示，看已计算的 S_{f−1}：
    （a）S_{f−1} 为提示：含 f 的提示段单列为“窗口前已启动”，不计入误报比例的分子与分母，只报告件数；
    （b）S_{f−1} 为非提示：该段在窗口首日开始，s = f，按规格第八节第 5 条正常分类；
    （c）S_{f−1} 无法确定：抛异常、停下报告，不归类。
12. 收益区间 j（第 j−1 日收盘 → 第 j 日收盘）一律以区间末日 j 标记。事件窗口置零与前后两半划分（2017—2019、2020—2022）都按区间末日判断。
13. 前后两半的 Δ 只有同为正或同为负才算方向一致，任一半等于 0 都算不一致。事件窗口置零后，重算的 Δ ≤ 0 就算“变号”。两者都只降低结论强度。

以下第 14 至 19 条为 2026-10-02 负责人批准（《阶段二问题裁决》第三节原文）。

14. **提示段起始日无法判断：**在窗口内，提示段开头的前一信号日状态为“无法确定”，并影响起始日判断时，抛异常、停下报告，不自行归类。补构造测试。
    - （对应第 3 项。窗口首日的情形仍按第 11 条（c）。）
15. **在 P 当日开始的提示：**提示在 P 当日新开始（S_P 为提示、S_{P−1} 为非提示），之后在 T3 前解除且没有再开始，按规格字面归“新提示达标”。补构造测试。
    - 这表示曾及时产生新提示，不表示持续覆盖，也不表示已完成保护。代码注释与汇报用语照此写。
    - （对应第 4 项。）
16. **自身亏损时的措辞：**
    - 候选期末对数净值 < 0 时，只如实列出候选、参照、一直持有三者的自身收益，以及年化相对净值增长率。
    - 只有候选确实比参照少亏（候选亏损，且 Δ > 0）时，才可以写“相对参照少亏”。其余情形只用中性的数值描述，不写“少亏”“多赚”“盈利”“收益提高”。
    - 措辞不改变登记的类别判定（A、B、C、D 与计算无效照登记第七节第 6 小节）。
    - （对应第 5 项，补充登记第七节第 7 小节未覆盖的情形。）
17. **跳过、预期失败、意外通过：**
    - 这三类按 pytest 的原结果单列件数。
    - 访问审计结果另行保留，不被测试结果掩盖：测试即使最终跳过或预期失败，只要发生过被拦截的访问，仍报告为“未完成（被拦截）”；有子进程或 ctypes 记录的，仍报告“覆盖不完整”。
    - （对应第 6 项。）
18. **R2 标签函数的输入前提：**
    - 阶段二的 `labels_r2` 检查传入行的日期顺序、重复日期与空价格，违反即抛异常。
    - 整行缺失（某个交易日不在序列中）由阶段三的数据入口对照明确的交易日轴检测。
    - `labels_r2` 的文档字符串必须声明前提：“输入已通过交易日完整性校验”。正式入口不得绕过这一校验。
    - 阶段三必须补“整行缺失时报错”的构造测试；这一要求同时记入状态表阶段三的待办。
    - （对应第 8 项。修订稿四 2.1 中“某个交易日缺收盘价时抛异常”在阶段二只指空价格。）
19. **事件窗口置零的稳定性警示：**
    - 每个事件分别置零一次；任一事件置零后的 Δ ≤ 0，即触发该项稳定性警示。
    - 只有原类别 A、B 因警示降为“证据不稳定”，C、D 不变。
    - 报告用语为“置零后不再为正”，不把等于零称为严格反号。
    - （对应第 10 项；与第 13 条一致。）
