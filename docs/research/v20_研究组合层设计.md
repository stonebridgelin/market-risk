## 二、入口与结果对象（第 4、5 条）

### 1. 三个显式入口

| 入口 | 签名 | 用途 | 限制 |
| --- | --- | --- | --- |
| `run_window(snapshot, spec, parameters, candidates) -> WindowResult` | 对显式给出的候选集合计算一个评价窗口的全部分层结果；不选择、不检验 | 开发期、冻结评价、构造验收 | 用途与窗口由 `spec` 决定（第三节）；`spec.purpose` 为开发期时 `candidates` 必须恰为模块内登记的 `REGISTERED_CANDIDATES`（第三节第 3 条） |
| `select_development(result, tolerance) -> DevelopmentSelection` | 调用 `selection.select` | **只接受** `result.spec.purpose is Purpose.DEVELOPMENT` | 否则抛 `ResearchRunError`；`result.stop` 不为 None 时也抛（候选记录不完整，不得选择）；`result.candidates_requested == REGISTERED_CANDIDATES`、记录条数 27、顺序 0…26 |
| `confirmatory_input(result, candidate, period) -> ConfirmatoryInput` | 组装冻结候选的检验输入 | 只接受 `Purpose.FROZEN` 或 `Purpose.CONSTRUCTED`；`candidate` 须在 `result.candidates` 中 | 只组装，不运行。检验由外层在授权后直接调用 `confirmatory.confirmatory_test(data, parameters)`；本模块**不提供**运行检验的包装函数，`period` 字符串只进入 `ConfirmatoryInput.period` 作措辞，不触发任何检验 |

### 2. 结果对象

- `WindowResult` 为冻结 dataclass，不含 `selection` 字段。选择结果放在独立对象 `DevelopmentSelection(window: WindowResult, selection: SelectionResult, tolerance: float)`；不在 `WindowResult` 上原地填入。
- 顶层 `frozen=True`；嵌套映射用 `types.MappingProxyType`，序列用 `tuple`。设计承诺只到此为止：`frozen=True` 保证字段不可重绑定，嵌套容器的不可变由上述类型保证，调用方不得依赖其他保证。

## 三、窗口参数 `WindowSpec`（第 4 条）

```python
class Purpose(Enum):
    DEVELOPMENT = "开发期选参"
    FROZEN = "冻结候选评价"
    CONSTRUCTED = "构造验收"

class Continuity(Enum):
    COMPLETE_TRADING_AXIS = "自各资产历史起点至 E 的 NYSE 交易日轴完整（整行缺失、多出日期均已由入口 check_trading_axis 拒绝）"

@dataclass(frozen=True)
class InitialStates:               # 登记第四节第 1 小节的初始快照，显式传入，不在组合层内写默认值
    channels: ChannelInitial       # 登记值 convergence.REGISTERED_CHANNELS
    system: SystemState            # 登记值 convergence.REGISTERED_SYSTEM
    reference: Risk                # 登记值 convergence.REGISTERED_REFERENCE

@dataclass(frozen=True)
class WindowSpec:
    purpose: Purpose
    first_return_day: dt.date | None   # 评价首个计入收盘日（j₀ 的日期）；None 只允许 DEVELOPMENT 与 CONSTRUCTED
    last_day: dt.date                  # E；须等于 snapshot.day
    histories: Mapping[str, dt.date]   # 资产 → 登记历史起点；键须恰为 {"SPX", "QQQ"}
    initial: InitialStates
    continuity: Continuity             # 只有一个合法值；记录入口承担的交易日轴验证责任
```

**历史输入范围与计入收益窗口分开：**

| 量 | 含义 | 来源 |
| --- | --- | --- |
| 历史输入范围 | `snapshot.days`（`axis`），自较早的历史起点至 E | 快照 |
| 计入收益窗口 | 收盘日 `days = axis[j0 : E_index + 1]`，收益区间 j₀→j₀+1 … E−1→E，共 `n = E_index − j0` 个 | 本节 |
| `E_index` | `len(axis) − 1`，`axis[E_index] == spec.last_day == snapshot.day` 否则 `ResearchRunError` | 裁决第八节 |

**起点 j₀ 的确定（`start_basis` 记入结果）：**

| 用途 | `first_return_day` | j₀ | 结果中的 `start_basis` |
| --- | --- | --- | --- |
| DEVELOPMENT | 必须为 None | `convergence.common_start_index(t0, [27 组 system_index, 主参照全局收敛行号], offset, len(axis))` | “共同起点 j₀ = max(t0 + 63, κ_全 + 1)，按登记 27 组与主参照计算” |
| FROZEN | 必须给出，且在 `axis` 上 | `j0 = axis.index(first_return_day)`。先按同样方法算出 `j0_min`（只用给定的冻结候选与主参照）；要求 `j0 ≥ j0_min` 且 `n ≥ 1`。不满足：停止，出口“固定窗口不满足预热或收敛条件”，记录 `j0_min` 日期与 `first_return_day`；**不推迟起点** | “固定起点（锁定记录给出）；预热与收敛前提 j₀_min = … 已核对” |
| CONSTRUCTED | 两种都允许 | None 时按给定候选集合算共同起点（不要求 27 组）；给出时同 FROZEN | 相应写明 |

冻结评价只计算显式给出的冻结候选；窗口起点由 `first_return_day` 固定，参数由 `RunParameters` 显式给出，不因候选集合变小而重算出不同的窗口，不隐式重选，不因前提不满足而推迟起点。`j0_min` 只是前提检查，不是起点。

| --- | --- | --- |

| 主参照收敛 | `reference_convergence(trend[t0+1:], 200)` 返回**局部位置** p；全局 = `t0 + 1 + p` | 源码注释 |

## 六、`run_window` 的调用顺序

1. 校验 `spec`、`parameters`、`candidates`（不一致 → `ResearchRunError`，这是调用方错误，直接抛出，不记入 `stop`）。
2. 输入派生量：`inputs.snapshot_asset_days(snapshot, "SPX"/"QQQ", windows)`、`snapshot_trend_days(snapshot, "SPX", windows)`。
3. `t0`；`NoStartError` → 出口“无法确定 t0”。
4. 每候选收敛、主参照收敛；`NotConvergedError` → 出口“始终不收敛”。
5. 起点 j₀（第三节）；`EmptyWindowError` → 出口“评价窗口为空”（带 `detail`）；固定起点不满足 → 出口“固定窗口不满足预热或收敛条件”。
6. `days`、`closes = {asset: snapshot.series(asset)[j0 : E_index+1]}`、`prefix = nav.basket_prefix(days, closes)`。
7. 一直持有（只算一次）：`prefix.first_missing is None` → `nav.simulate_hold(days, prefix.values, positions, tolerance)`；否则 `Unavailable(prefix.missing)`。
8. 每资产标签历史与 R2 事件（第九节）：`labels_r2.r2_events(asset, rows, cutoff=E, thresholds)`；`MissingPriceError` → 该资产事件 `Unavailable`；`LabelInputError`/`UnexpectedLabelError` → 停止。
9. 主参照：完整逐日记录与净值模拟信号（第五节两种切片）→ `signal_targets` → `switches` → 信号模拟净值（第七节）→ `simulate_policy_with_gaps`。
10. 每候选（登记顺序）：两种切片 → 信号模拟 → 执行政策模拟 → R2 窗口（状态来自 `system_full`）与 `r2_result`、`segment_ledger`（每资产；该资产事件不可得则为 None）→ `r1_result` → 分段报告 → `CandidateRecord`。
    允许的复用：输入派生量只算一次；同一 (K, θ) 的通道路径与证据序列只算一次供 h 不同的候选共用（`run_channels` 不依赖 h）；收敛仍逐候选调用 `candidate_convergence`。不改算法、不减候选、不放宽断言。
11. 组装 `WindowResult`；`parameters.diagnostics` 为真时最后计算诊断（第十四节），不回写任何业务字段。

任一候选或主参照出现停止类出口（第十二节）：保存已完成候选的结果与停止记录，**不再计算其余候选，不选择**。

## 七、缺价时的净值分层（第 6 条）

`nav.BasketPrefix.values` 只是首个缺价日之前的收益前缀，长度 `first_missing − 1`（或 0），**不得**传给完整窗口的 `simulate_targets` / `simulate_hold`。

| 对象 | 价格完整 | 窗口内有缺价（`prefix.first_missing is not None`） |
| --- | --- | --- |
| 信号目标与切换 | `signal_targets(days, signals, positions)`、`switches(targets, positions)` | 照常生成（只依赖信号） |
| 信号模拟净值 | `simulate_targets(targets, prefix.values, positions, tolerance)` → `NavResult` | `Unavailable(missing=prefix.missing)`，不调用 `simulate_targets` |
| 一直持有净值 | `simulate_hold(days, prefix.values, positions, tolerance)` | `Unavailable(prefix.missing)` |
| 执行政策研究模拟 | `simulate_policy_with_gaps(...)` → `PolicyResult` | 同一调用 → `PartialPolicyResult`（保留缺价前已确定的 `targets`、`executions`、`returns`、`undetermined`、`missing`） |
| R1 | `r1_result(signal.wealth, hold.wealth, ratio)` | `r1_result(None, None, ratio)` → `computable=False` |
| `CandidateRecord.log_wealth` | `NavResult.log_wealth` | None |

不补价格、不拼跨期收益、不恢复研究净值。`Unavailable` 为组合层的冻结 dataclass：`missing: tuple[tuple[str, dt.date], ...]`，与 `nav.NavUnavailable.missing` 同形。

### 2. 日期边界 `(start, end]` → 净值下标（负责人修正第 5 条）

窗口净值序列 `W[0..n]`，`W[i]` 为 `days[i]` 收盘的净值（`NavResult.wealth`，`W[0] = 1`）；收益 `r[i]`（i = 1..n）为 `days[i−1]` 收盘到 `days[i]` 收盘，以区间末日 `days[i]` 标记（补充第 12 条）。分段用**日期边界** `(start, end]`，`start`、`end` 可以是任何日历日期（年末、周末、休市日都正常映射）；轴已通过入口的交易日完整性检查，所以“应有交易日缺失”在入口就被拒绝，不会在这里出现，二者不混为一谈。

| 项 | 规则 |
| --- | --- |
| 计入段的收益 | 区间末日满足 `start < days[i] ≤ end` 的 `r[i]` |
| 下标 | `i1 = max(bisect_right(days, start), 1)`（第一个末日 > start 的区间；`r[0]` 不存在故至少为 1）；`i2 = bisect_right(days, end) − 1`（最后一个末日 ≤ end）；`i2 < i1` → 无收益区间 |
| 净值端点 | 段首 `a = i1 − 1`（首个计入收益之前的收盘日净值 `W[a]`，保留作起点）；段尾 `b = i2`；净值切片 `wealth[a : b+1]`，调用 `r1.segment_drawdown_ratio(signal, hold, a, b)`；不重新初始化、不重算策略。熊市段 `(高点收盘日, 低点收盘日]`：进入高点当天之前的收益（末日 ≤ 高点日）不计入 |
| 覆盖标注 | `start ≥ days[0]` 且 `end ≤ days[n]` → 完整覆盖；`start < days[0]` 或 `end > days[n]` 而仍有收益区间 → 部分覆盖；`i2 < i1` → 无收益区间（含整段在窗口之外）；信号或一直持有净值 `Unavailable` → 不可计算 |
| 报告 | 申请边界 `(spec.start, spec.end]` 与实际净值端点 `days[a]`、`days[b]` 都写入报告 |

输出 `SegmentReport(spec, coverage, first_nav_day, last_nav_day, returns_count, drawdown_ratio, undefined)`；`returns_count = b − a`；`drawdown_ratio` 为 `segment_drawdown_ratio` 的返回（一直持有段内回撤为 0 时 None 且 `undefined=True`）。

### 3. 相邻分段不重复记账（构造例）

`days = D0..D10`，段甲 `(D2, D5]`、段乙 `(D5, D8]`：甲计入 `r[3], r[4], r[5]`，段首 `W[2]`、段尾 `W[5]`；乙计入 `r[6], r[7], r[8]`，段首 `W[5]`、段尾 `W[8]`。`r[5]` 只在甲中计入一次；`W[5]` 同时是甲的尾端点与乙的首端点，是净值端点不是收益。验收：`3 + 3 = 8 − 2`；两段计入收益的末日集合互不相交且并集为 `{D3..D8}`；`Σ ln(1+r)` 两段之和等于 `ln W[8] − ln W[2]`（容差 1e-12）。另验收：边界取周末或休市日（如 `start` 为星期六、`end` 为 1 月 1 日）时映射到相邻交易日区间且不报错；`start < days[0]` 的部分覆盖；`end ≤ days[0]` 的无收益区间。

## 十二、异常：根因与出口分开（第 1、9 条）

### 1. `r2.R2Undeterminable`（本轮实现范围内）

- 新增 `class R2Undeterminable(R2Error)`，文档：“‘无法确定’的状态影响了分类（停下报告，不归类）；不是输入不合法。”
- 只替换三个**语义位置**的 `raise`（按语义定位，不依赖行号）：(a) `judge_event` 中 S_P 为提示、S_{P−1} 无法确定且 `[P, T3)` 内没有确定的转换，影响“新提示达标”与“提示中断”的区分；(b) `judge_event` 中 `[T3, Tr]` 内有无法确定状态，影响“迟到”与“漏报”的区分；(c) `prompt_segments` 中提示段开头的前一日状态无法确定，起始日无法判断。
- 其余 `R2Error`、判断、返回值、报错正文不变。既有测试保留；新增三处 `pytest.raises(R2Undeterminable)` 与一处“普通输入错误仍为 `R2Error` 且不是 `R2Undeterminable`”的检查。

### 2. 停止记录 `StopRecord`

字段：`exit`（出口）、`object`（候选键 / 主参照 / 一直持有 / 资产 / 公共）、`stage`、`exception_type`（原始异常类名）、`reason_code`（异常的 `reason` 属性，没有则 None）、`message`、`detail`（如 `EmptyWindowError.detail`、`j0_min`）、`traceback`（只在未预期异常时保留）。根因不由出口推出，只来自 `exception_type` 与 `reason_code`。

## 三、缺价结果的结构化原因

`Unavailable` 扩为结构化记录并在组合层输出中实际保存，统一用于信号净值、一直持有净值与每资产 R2 事件三处：

```python
Unavailable(missing: tuple[tuple[str, dt.date], ...],   # （资产，日期），来自 BasketPrefix.missing 或 MissingPriceError 所在资产的缺价日集合
            reason_code: str,                            # 异常的 reason 属性或组合层判定码，这里恒为 "缺少必需价格"
            exception_type: str | None,                  # 实际异常类名（labels_r2.MissingPriceError）；由 prefix 预先分层时为 None
            source: str)                                 # "basket_prefix" | "labels_r2.r2_events"
```

- 不解析异常文字；`reason_code` 只取异常类的 `reason` 属性或组合层自身的判定；`missing` 对标签路径取该资产 `rows` 中价格为 None 的日期集合（组合层已持有 `rows`，不从消息中提取）。
- `CandidateRecord` 字段不变（None 表示不可计算）；结构化原因只在 `CommonOutcome.events`、`CommonOutcome.hold`、`ObjectOutcome.signal_nav` 中保存。
- 不扩大已验收算法模块的修改范围：`nav`、`labels_r2` 不改。
- 验收：第十五节 #3 断言 `signal_nav.reason_code == "缺少必需价格"`、`source == "basket_prefix"`、`missing` 等于构造的缺价（资产，日期）集合；#4 断言 `events["QQQ"].exception_type == "MissingPriceError"`、`source == "labels_r2.r2_events"`、`missing` 含起点日。
