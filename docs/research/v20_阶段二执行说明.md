## 执行方式的裁决

1. 插件的加载命令：日常带拦截的检查与那一次授权的记录模式回归，统一改用 `uv run python -m pytest -p tests.v20_data_guard`。其余范围与一次性限制不变。正式回归之前，先用临时构造测试验证实际插件可以加载；不得拿正式全量回归试错。
2. 阶段一的三个隔离测试保留，逻辑与期望不变，移至单独的 `tests/test_v20_isolation.py`，不混入插件自测文件；新增的源码静态检查也放在该文件。改动检查的排除路径相应增加这个文件。该文件只允许读取项目源码及进行模块导入检查；其中的子进程测试照实标“覆盖不完整”，不得删除测试来满足零子进程要求。
3. 跳过、预期失败、意外通过按 pytest 的原结果单列。同时保留访问审计结果：即使测试最终跳过或预期失败，只要发生被拦截的访问，仍须报告“未完成”；子进程或 ctypes 记录也不能被这些结果掩盖。
4. 授权回归在代码与测试的最终提交上运行一次；之后另作仅含状态表、汇报及审计摘要的文档提交。汇报列出被测试的提交号与后续文档提交号。回归之后若修改代码、测试或配置，须重新申请回归授权。

## 不变的要求

只用构造数据；不带拦截的全量回归只运行一次且只用记录模式；出现失败时不重跑、不修改既有测试或期望值，停下报告；完成后提交、推送并汇报，等待阶段二验收，不进入阶段三。
