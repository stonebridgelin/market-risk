## 三、特别审查一：读取函数是否会解析截止日之后的行情数值

**结论：`market_risk.data.market.read_series_file` 会整份解析文件，不能直接复用于行情读取。**

核实到的事实：

1. `read_series_file` 没有截止日参数，循环读完全部行，对每一行的 `value`（ETF 另有 open、high、low、close、volume）做数值转换。SPX.csv、QQQ.csv 都延伸到 2026-09-25（登记第零节），整份解析就会解析验证期与保留期的行情数值，与计划 C0、C1 的规定相抵触。
2. 它默认返回 `float`；`exact=True` 时才保留十进制文本。
3. `load_market_series`、`coverage_error` 同样整份读入后再用 `_window` 截断，属于“先读后截”，不满足“在读取入口停止解析”。
4. 现有代码里满足要求的是 `market_risk.wavewarn.inputs.series_until`（第二节），但它在 v1.x 专用模块里。

建议的替代做法（只说明，不实现；待批准后在阶段三实现，计划 3.1）：

- **行情读取**：v2.0 数据入口新写一个流式读取函数。逐行读取；每行先只取日期字段；日期必须严格升序；遇到第一条晚于截止日的行立即停止，不对该行及其后任何行的数值字段做转换；截止日晚于该评价窗口允许的上限时在打开文件之前拒绝。测试用构造文件证明：截止日之后的行即使数值字段是无法解析的文本，读取也不报错（说明没有解析它）。
- **文件级元数据**（计划 C0′）：与行情读取分开的另一个函数，只做三件事。哈希：以二进制方式读取文件字节计算 SHA-256，不经过文本解析。行数：按字节统计换行符。首末日期：只取第一条数据行与最后一条数据行的日期字段（逗号之前的部分），不读取、不转换同一行的数值字段。函数的返回类型里不包含任何行情数值。
- 两个函数都放在 v2.0 的读写模块里，纯计算模块不导入它们（加依赖方向测试）。

## 四、特别审查二：自助法抽样实现与 v1.2.1 规格是否逐条一致

**结论：`market_risk.wavewarn.paired_test.stationary_bootstrap_indices` 与 v1.2.1 规格逐条一致；函数自身不依赖任何 v1.x 的评价对象。**

先说明一处与指令不符的地方：仓库里没有 `wavewarn/statistics.py`。平稳自助法的抽样实现在 `src/market_risk/wavewarn/paired_test.py`（另有 `joint_test.py` 调用它）。

v1.2.1 规格原文（`docs/research/波段预警研究规格_v1.2.1.md` 第 377 行）：随机数用 NumPy `Generator(PCG64(seed))`，抽样顺序固定为：对 k = 1…B，先 `i = integers(0, n)` 取第一个位置；此后每个位置先抽 `u = random()`，u < 1/b 时 `i = integers(0, n)`，否则 i = (i + 1) mod n。

| 规格条文 | 实现（`paired_test.py` 第 41—56 行） | 是否一致 |
| --- | --- | --- |
| `Generator(PCG64(seed))` | `np.random.Generator(np.random.PCG64(seed))`；在全部 B 次重抽样之前创建一次，B 条序列共用同一个随机数流 | 一致 |
| 每条序列先 `integers(0, n)` 取第一个位置 | `position = int(generator.integers(0, length))` | 一致 |
| 此后每个位置先抽 `u = random()` | `uniform = float(generator.random())`，在决定下一个位置之前抽取 | 一致 |
| u < 1/b 时重抽 `integers(0, n)` | `uniform < 1 / block_length` 时 `int(generator.integers(0, length))` | 一致（严格小于） |
| 否则 (i + 1) mod n | `(position + 1) % length` | 一致（环形） |
| 每条序列长度 n | 第一个位置加 n − 1 次续行，共 n 个索引 | 一致 |

对 v1.x 评价对象的依赖：

- 函数自身：输入只有 n、b、B、种子（或外部给的生成器），输出是索引元组；不接触损失、标签、灯色或任何评价对象。
- 所在模块：模块级 import `market_risk.wavewarn.config.PairedParameters`（v1.2.1 配置里的一个数据类）。同一模块里的 `paired_stationary_test`、`zero_around_event`、`paired_robustness` 是 v1.x 的检验：统计量是损失差、p 值按 `value − total ≤ total` 计（左尾，负值为好），与登记第七节的右尾 `Δ*_k − Δ ≥ Δ` 方向相反；种子与区块长度也是 v1.x 的。这三个函数不复用。

需要注意的两点（都列入第六节）：`numpy` 在 `pyproject.toml` 里只约束为 `>=1.26`，没有锁定具体版本；第一个现有测试依赖仓库之外的参考文件。

## 六、疑问与发现的冲突

以下各项都需要负责人裁决或确认；每项附我的建议与理由。裁决之前我不按任何一种写法动手。

1. **指令中的文件名不存在。** 指令写 `wavewarn/statistics.py`，仓库里没有这个文件；抽样实现在 `wavewarn/paired_test.py`。本清单按实际位置评估。请确认这就是指令所指的实现。

2. **抽样函数的复用形式。** 两种做法：（甲）v2.0 直接 `from market_risk.wavewarn.paired_test import stationary_bootstrap_indices`，这会让 `wavewarn_v20` 依赖旧 `wavewarn` 包里的两个模块（`paired_test`、连带的 `config`）；（乙）在 v2.0 里另写同样的十余行，再用测试证明两份实现对登记的五个种子逐位相同。建议（甲）：同一份实现最直接地满足“抽样顺序同 v1.2.1”，且计划的静态检查只禁止导入旧通道与旧缺值模块，这两个模块都不在其列。若负责人希望 `wavewarn_v20` 完全不依赖旧包，则选（乙）。

3. **价格读入的精度没有写明。** v1.2.1 至 v1.4 读 SPX、QQQ 时经 `published_price` 四舍五入到两位小数；数据集文件按代码注释保存的是四位小数。登记第三节只写“`data/market/` 中 SPX 与 QQQ 的收盘价”，附录 A 提到数据集 SPX 为两位小数，没有写明 v2.0 计算用哪一种。这会影响 D ≥ θ_P、收盘价与均线比较等边界判断。建议沿用 `published_price`（两位小数），与旧版本读出同样的价格，也与附录 A 的写法一致。我没有读取数据文件，不知道两种读法在实际数据上是否有差别。

4. **数值类型没有写明。** 旧波段预警的规则计算用 `Decimal`，失败路径分析用 `float64`。登记的对账容差是 1e-10、检验用 NumPy 重抽样，暗示对数收益与净值用浮点。建议：价格、均线、D、门槛比较用 `Decimal`（门槛边界精确）；对数收益、净值、Δ 与重抽样用 `float64`。这一选择会影响“等于门槛”时的判定，所以请确认。

5. **`market_risk.config._read_yaml` 是带下划线的私有函数。** 仓库里已有两个模块跨模块使用它，旧 `wavewarn` 的四个配置模块则各自直接调用 `yaml.safe_load`。建议 v2.0 复用 `_read_yaml` 与 `ConfigError`，不另写第五份 YAML 读取；若负责人认为不应使用私有名字，则在 v2.0 配置模块里新写。

6. **git、gzip 与哈希工具的归属。** 计划第二节第 2 条把“哈希、gzip 写出”列为可复用工具，但现有实现都在 v1.x 专用模块里（第二节），直接 import 会连带加载 v1.x 的配置、评价与报告模块。建议：哈希复用存储层的 `provenance_store.file_sha256`；查找 git 与 gzip、调用 git、`gzip -n` 压缩在 v2.0 的读写模块里新写（做法与 v1.4 相同，压缩结果的字节与旧做法一致）；`storage.runs.git_info` 的“是否干净”口径不含 `results`、`reports` 等目录，建议不用于 v2.0 的运行记录。这些函数在阶段四才用到，授权甲范围内只需要哈希。

7. **数据集版本绑定是否另外核对 manifest。** 登记第零节给出两份 CSV 的 SHA-256、行数与首末日期；计划 3.1 只要求核对这三项。`data/market/manifest.json` 里也记有每个序列的哈希，我没有读取它，不知道它与登记第零节的数值是否一致、哈希的计算口径是否相同（`market.py` 里是对 UTF-8 文本算小写哈希）。建议阶段三只按登记第零节的数值、按文件字节核对，不读取 manifest；如需加一道 manifest 核对，请另行指示。

8. **交易日历没有直接的行为测试，第三方库版本也没有锁定。** `stock_trading_days` 的返回值没有被任何测试直接断言；`pandas-market-calendars` 在 `pyproject.toml` 里只约束为 `>=4.4`。v2.0 的日期轴从 1990 年起，库的版本变化若改动了某个历史休市日，日期轴与“缺价”的判断会随之改变。建议新增构造测试，固定若干已知的历史休市日与某几年的交易日个数（期望值取自交易所公告，由产品经理确认后写入，不由被测函数回写），并在阶段四的运行记录里写入该库的版本号。

9. **`numpy` 版本没有锁定。** `pyproject.toml` 里是 `numpy>=1.26`；现有参考索引文件注明由 NumPy 2.4.4 生成。固定种子的逐位复现依赖 NumPy 的随机数流不变。建议阶段五的锁定记录写入 NumPy 版本，并用测试固定登记的五个新种子的前若干条索引。

10. **现有的抽样参考测试依赖仓库之外的文件。** `test_stationary_bootstrap_s1_s4_first_ten_match_independent_reference` 读取 `../market-risk-design-samples/v1.2.1/stationary_bootstrap_reference.json`（或环境变量 `MARKET_RISK_DESIGN_SAMPLES` 指向的目录），文件不存在时测试失败。它固定了被复用函数的行为，但证据不在本仓库里。建议 v2.0 新增的种子测试把期望索引放在仓库内的测试数据中，来源为阶段三的独立复核工具。

11. **`storage/paths.py` 没有研究输出与研究配置的路径函数。** 旧 `wavewarn` 模块用 `root / config.output` 自行拼出 `reports/research/...`。CLAUDE.md 第 9 条与计划通用纪律第 3 条要求路径只由 `storage/paths.py` 生成，这意味着 v2.0 需要在 `paths.py` 里新增路径函数（配置文件、输出目录、测试数据）。`paths.py` 是共享模块，不属于 v1.x 模块；新增函数不改动任何已有函数。建议允许这样的新增并配测试；请确认这不算“修改旧模块”。

12. **分位数的计算方法没有写明。** 登记第七节第 3 小节写“区间为 Δ* 的 2.5% 与 97.5% 分位数”，没有写插值方法。v1.x 用 NumPy 默认的线性插值，源码注释为“方法在负责人确认后锁定”。建议沿用线性插值并写入配置。此项属于阶段二，先提出，不影响本清单的审批。

13. **已批准修正条目的来源标识。** 计划 3.3 称 `correct` 条目的来源标识为 `correct:yahoo`。源码里这个标识由 `data/corrections.py` 写入该日所在行的 `source` 列（`correct:` 加原来源名）。我没有读取数据文件，不能确认 QQQ 2008-09-08 一行的实际内容；阶段三按“读取入口逐行读 `source` 列、遇到未登记的来源标识即抛出异常、`correct:yahoo` 放行”来实现是否符合计划的意思，请确认。
