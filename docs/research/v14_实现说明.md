## 实现中的口径

1. **解除规则 F 的接入方式。** `step_system` 在开头对版本 `F` 分派到新函数 `release_f_step`；E1、E2、E3、X1、X2 与 P0 护栏的判断代码一行未动。接入后重跑 v1.3 开发期评价，输出与入库文件逐字节相同。
2. **红→黄只看红灯通道。** 按登记原文，红→黄要求“全部红灯通道当日有效且未激活”与两指数 Q ≥ K；黄通道 P 是否有效、是否激活不影响这一步。黄→绿要求全部通道。
3. **“所需输入缺失”。** 解除规则 F 需要的输入是参与该步的通道与两指数的 Q；两指数当日都有收盘价才算 Q 的输入有效。任一缺失时不降级，数据状态记“沿用”。
4. **MR 的初始状态。** 与其他通道相同：t0 为初始快照（已武装），次日起更新。输入有效时“当日激活 ⇔ 当日 SPX 收盘价低于其 200 日均线”，与参照行信号逐日相同（测试覆盖自均线可用起的全部开发期交易日）。
5. **转绿延迟的分位数**用与退出代价相同的线性插值；g=Tr 时延迟为 0。
6. **各级候选数不互斥**：第二级统计的是满足非绿占比上限的全部候选（含也满足转绿要求的）；程序只在前一级为空时才用后一级。
7. **补充历史**的 t0′ 规则同 v1.3（两资产的收盘价、63 日高点与回撤、20 日新低窗口、MA50 首次全部具备）；SPX 的滚动窗口（含 MR 的 200 日均线）用到了窗口起点之前的 SPX 价格。两次熊市的对照列出全部九组纯价格版设定与始终绿、200 日均线。
8. **新代码不写参数默认值**：v1.4 新增模块的函数参数都由调用方显式传入，数值来自配置对象。
9. **尚未实现**：登记第五节在验证期才用到的“SPX 跌幅 15% 以上的每个 ZZ 事件中的执行暴露与回撤”。

入口：

- `uv run market-risk wavewarn v14-rehearse-validation --lock-draft docs/research/v14_锁定记录_草稿.md`：开发期演练 → `reports/research/wavewarn_v14/validation_rehearsal_development/`。

- `uv run market-risk wavewarn v14-validate --lock-record <路径>`：正式验证期运行，只能一次 → `reports/research/wavewarn_v14/validation/`。**本批没有运行。**

口径：

1. **窗口。** 模型自 t0 连续运行；验证期计入区间起点为 2017-01-03，回撤参考高点在该日重置，ē 按验证期计入区间计算；退出代价、转绿延迟与大跌事件表纳入高点 P ≥ 2017-01-03 的事件；事件账用 `validation_scope_rule`（高点前 20 天的灯色可落在 2016 年）。演练窗口为开发期（起点 j₀，事件门槛 τ）。
2. **主检验。** d_j 只按整个窗口的 ē 计算一次；区块 10/20/40 用各自的登记种子；前后两半、删除置零日期用主设定的区块与种子；逐事件剔除只重算 Σd 并标出是否变号。
3. **截断不变性 (c) 的测试方式。** ZZ 标签按设计是事后标签，输入截断后尾段的标签会改变。测试分两层：状态（灯色、数据状态、激活通道、原因、收敛日）在截断前后逐日相同；损失在使用同一套标签时逐日相同。
4. **锁定记录的哈希**取各文件在 HEAD 中已提交的内容（LF 换行），不取工作区文件，避免本机检出时换行转换造成的不一致。
5. **运行中途失败。** 验证期命令一开始就创建输出目录并写入 `lock_record.json`；此后再次运行会被拒绝，需由负责人决定如何处理。
